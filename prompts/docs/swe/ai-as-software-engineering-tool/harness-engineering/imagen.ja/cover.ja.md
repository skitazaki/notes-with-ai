# 画像生成プロンプト — ハーネスエンジニアリング

## コンセプト

**ハーネスエンジニアリング** というタイトルのカバー画像を作成してください。一つの明快なエンジニアリングの循環を示し、6つの責務は循環を支える機能として配置します。6つを同列の独立した箱にしないでください。タスク設定と信頼できる文脈がモデルに渡す作業内容を整えます。ツール権限はモデルが要求できる操作を制御し、実行の隔離は操作が影響する場所を制約します。フィードバックと可観測性は実行結果をモデルの次の行動につなぎます。状態と連携は計画、結果、担当、引き継ぎを記録します。人のレビューは証拠を確認し、レビューのフィードバックを次の反復に返します。

## レイアウト

**16:9** の横長構図にしてください。目安は **1536 × 864 ピクセル**です。左から右へ読む主作業経路を最も目立たせます。入力領域、一つの大きなハーネス境界、人のレビュー領域を配置します。

1. **入力** — **タスク** と **参照資料**を含む小さなカードです。これらは入力情報であり、ハーネスの責務分類ではありません。
2. **ハーネス** — 中央の最も目立つ領域です。一つの明確な外枠で囲みます。内部上部に、**タスク** + **参照資料** → **タスク設定** + **信頼できる文脈** → **モデル** → **ツール権限** → **実行の隔離** + **制約された実行環境**という作業経路を描きます。タスク設定と信頼できる文脈はモデルの前に一つのまとまりとして置きます。ツール権限はモデルと実行環境の間にあるゲートにします。実行の隔離は制約された実行環境を囲む境界として表し、実行環境の後ろに続く工程にはしません。
3. **人のレビュー** — **証拠** と、それを確認する人を含む小さな領域です。

**フィードバックと可観測性**は、制約された実行環境の結果からモデルへ戻る経路として配置します。**状態と連携**はハーネス境界内の下部に、作業の記録を表す横長の帯として置きます。ラベルの下に、小さな一行の例 **計画 · 結果 · 担当 · 引き継ぎ** を表示します。この4語は同じ帯の中の通常のテキストとし、個別の箱、アイコン、工程にはしないでください。この帯には、タスク設定、実行結果、人のレビューから点線の接続を三つだけ引きます。循環全体にわたる作業状態を記録するもので、新たな実行工程にはしません。

列を接続し、次のフィードバック循環を示します。

- 入力 → タスク設定 + 信頼できる文脈: 入力領域から、準備をまとめた領域へ明確な順方向の矢印を一本引きます。
- 作業経路: 準備 → モデル → ツール権限 → 制約された実行環境。実行の隔離は実行環境を囲む境界として描き、順番に処理する段階にはしません。
- 実行環境 → 証拠 → 人のレビュー: 実行結果の証拠をレビュアーへつなぎます。
- フィードバックと可観測性: 実行結果をモデルへ戻す矢印を一本引き、順方向の作業経路と見分けられるようにします。
- 人のレビュー → ハーネス: **人のフィードバック** とラベルを付けた別の曲線矢印をタスク設定へ戻し、レビューが次の反復に反映されることを示します。
- 状態と連携: 三つの点線は下部の記録帯で止めます。記録帯を実行経路に含めたり、フィードバック矢印として使ったりしないでください。

接続点には十分な間隔を設けます。順方向の作業、実行結果のフィードバック、人のレビューのフィードバック、状態記録を、矢印の向きと線種で明確に区別します。矢印は短く直接的にし、交差させたり無関係な要素を通過させたりしません。主経路の周囲には十分な余白を保ちます。

## 視覚要素

- 画像内の正確なタイトルは **ハーネスエンジニアリング** です。サブタイトルは使わないでください。
- 次のラベルだけを使用してください。**入力**、**タスク**、**参照資料**、**ハーネス**、**タスク設定**、**信頼できる文脈**、**ツール権限**、**実行の隔離**、**フィードバックと可観測性**、**状態と連携**、**計画**、**結果**、**担当**、**引き継ぎ**、**モデル**、**制約された実行環境**、**証拠**、**人のレビュー**、**人のフィードバック**。
- 入力カードでは、タスクと参照資料を細い水平線で区切った別々の行にします。入力項目をハーネスの責務そのものとして扱わないでください。
- 6つの責務を三つの機能グループにまとめます。準備（**タスク設定**、**信頼できる文脈**）、行動の制御（**ツール権限**、**実行の隔離**）、学習と継続（**フィードバックと可観測性**、**状態と連携**）です。配置とまとまりで役割を表し、同じ大きさの6枚のカードにしないでください。
- 線と配置で四つの関係を区別します。順方向の実行、実行結果からモデルへのフィードバック、人のレビューからタスク設定へのフィードバック、状態と連携への点線の記録リンクです。
- 実行の隔離は制約された実行環境を囲む境界として描きます。ツール権限はその境界の手前にあるゲートです。両者の役割を混同しないでください。
- 状態と連携は作業全体にわたる記録帯として配置し、その中に **計画 · 結果 · 担当 · 引き継ぎ** を一行で示します。主作業経路より控えめにしてください。処理経路の一段階にはしないでください。
- 証拠は人のレビューに届きます。人へのフィードバック経路と、実行結果からモデルへのフィードバック経路を分けてください。

## スタイル

技術ドキュメントサイト向けの、落ち着いた、情報を整理して伝えるインフォグラフィックにしてください。温かみのある明るい背景、濃紺の文字と線、控えめなティールとアンバーを使います。中央列を最も目立たせ、左右の列は簡潔にし、ハーネスの境界を明瞭にします。記事本文のカラム幅でもラベルが読める大きさにしてください。アイコンは補助的に使い、構成と矢印で意味を伝えます。

## 禁止事項

- 指定したラベル以外のラベルを追加しないでください。
- 6つを同列の箱にしたり、無関係な責務の一覧にしたり、記事の各セクションを画像内のブロックに対応させたりしないでください。
- 実行の隔離を制約された実行環境の後続工程にしないでください。環境を囲む境界です。
- 実行結果からモデルへの循環と、人のレビューからタスク設定への循環を混同しないでください。
- 状態と連携を実行経路に通したり、フィードバック矢印の接続先にしたりしないでください。
- 計画、結果、担当、引き継ぎを個別のカード、工程、矢印にしないでください。
- 線の交差、向きが曖昧な矢印、装飾目的の矢印、ラベルのない循環を描かないでください。
- ツール権限と実行の隔離を一つにまとめず、6つの責務を省略しないでください。
- ファイルシステム、ネットワーク、認証情報、本番環境への無制限なアクセスを描かないでください。
- 事業者名や製品名、ロゴ、メトリクス、架空のコード、透かし、装飾的な回路模様、指定外のワークフロー段階を加えないでください。
- **16:9** の比率を守り、十分な余白を保ってください。
