# 画像生成プロンプト — コーディングエージェントのアーキテクチャ

## コンセプト

**コーディングエージェント** というタイトルの、分かりやすいカバー画像を作成してください。人と利用サーフェス、モデルの能力、ローカルまたはリモートのリポジトリ実行環境、独立した開発システムをつなぐ中央の調整役として、コーディングエージェントを示します。タスクの工程ではなく、アーキテクチャの要素と関係に焦点を当ててください。

## レイアウト

**16:9** の横長構図にしてください。目安は **1536 × 864 ピクセル**です。エージェントを中央に置き、周囲との接続を追いやすくします。

```text
開発者 / レビュアー ↔ 利用サーフェス ↔ コーディングエージェント ↔ モデルアクセス
                                                   ↕
                         ローカルまたはリモートの実行環境 ↔ 外部システム
                                      │                              │
                                      └────→ 検査と証跡 ←───────────┘
                                                   │
                                                   └──→ 開発者 / レビュアー
```

実行環境には、リポジトリのチェックアウトとローカルツールを含めます。外部システムは実行環境の外側に置き、見えるネットワーク境界を越えて接続します。モデルアクセス、実行環境、外部システムをそれぞれ別のまとまりとして示し、直接的な接続に絞ってください。

## 視覚要素

- 画像内の正確なタイトルは **コーディングエージェント** です。ほかに大きな文字は使わないでください。
- 単純なアイコンで、利用サーフェスの選択肢を3つ示してください。**ターミナル**、**デスクトップアプリ**、**エディタ / プラグイン**。
- 少なくとも2つの異なるモデル系列を示し、それぞれに複数のエンドポイントを個別のノードとして描いてください。例: **モデル系列 A** に **エンドポイント A1** と **エンドポイント A2**、**モデル系列 B** に **エンドポイント B1** と **エンドポイント B2**。モデル系列はモデルのグループ、エンドポイントは個別に接続可能な提供先だと分かるようにします。系列ごとにアイコンを一つ置くだけで、エンドポイントのノードを省略しないでください。
- アクセス形態はエンドポイントとは別の選択肢として示します。モデル系列・エンドポイント・アクセス形態が一対一に固定されているように描かないでください。
- 境界のある実行環境に、リポジトリのチェックアウト、ファイルシステム、Git、シェルを表す記号を配置してください。ローカル実行とリモート実行は選択肢として区別します。
- 外部システムは独立したものとして示し、**Issue 管理**、**ナレッジベース**、**ホスト型リポジトリ**、**CI** を簡潔なアイコンで表します。
- **検査と証跡** に入る二つの異なる情報経路を示してください。実行環境からはローカルテスト、ビルド、静的解析の結果が届きます。外部システムからは CI の結果、Issue の状態、レビュー情報が届きます。両方から証跡ノードへ矢印を向け、そこから開発者 / レビュアーへ一つの矢印をつなぎます。
- 文脈や依頼がエージェントへ届き、ツールの結果が戻ることも示してください。検査と証跡が外部システムからしか得られないように見せないでください。
- エージェントの実行環境と、ネットワーク越しの外部システムとの間に境界を一つ設けます。タスクの工程は追加しないでください。

## スタイル

技術ドキュメントサイト向けの、落ち着いた、情報を整理して伝えるシステム図にしてください。温かみのある明るい背景、濃紺の線、控えめなティールとアンバーを使います。シンプルな幾何学アイコン、明確なグループ分け、十分な余白、読みやすいサンセリフ体を用いてください。記事本文のカラム幅でも読めるようにします。

## 禁止事項

- サブタイトル、事業者名や製品名、ロゴ、メトリクス、架空のコード、透かし、装飾的な回路模様を入れないでください。
- モデル、利用サーフェス、実行環境のツール、外部サービスを同じ構成要素として描かないでください。
- エンドポイントのノードやラベルを省略し、モデル系列をアイコンだけで表さないでください。
- 各モデル系列にエンドポイントが一つだけある、またはアクセス形態が特定のエンドポイント一つにしか対応しないと示さないでください。
- 独立した外部システムを直列のワークフローにしたり、すべての連携が必須だと示したりしないでください。
- 詳細な権限分類、協働パターン、ワークフローの段階を追加しないでください。
- **16:9** の比率を守り、カバーとして読める簡潔な構図にしてください。
