# 画像生成プロンプト — アーキテクチャズームマップ

タイトル: 「アーキテクチャズームマップ」

明るい背景、16:9 の横長レイアウト、5〜6色程度の落ち着いた配色で、クリーンな編集向けインフォグラフィックを作成してください。ベクター風の図形と読みやすいラベルを使い、ベンダー中立に保ってください。ロゴ、製品ブランド、クラウドやデプロイメント図は使わないでください。

この図は、アーキテクチャの思考がまず観点によって分類され、その後に支援的なガイダンスが設計判断に影響する、ということを説明してください。中心の整理軸は「アーキテクチャの観点」です。そのハブから、5つの均衡の取れた分岐を描いてください: 構造、運用、戦略、責任分担、表現。ラベルは以下のようにしてください: 構造: レイヤー; 運用: プレーン、フローとパイプライン; 戦略: ピラー; 責任分担: 責任境界; 表現: ビューとビューポイント。

各分岐は見た目は違いながら、相互に整合した視覚的なバランスを保ってください。構造はレイヤー構造や分解のように見え、運用は実行時の挙動とシステムを横断する動きとして見え、戦略は品質、制約、優先順位を示唆し、責任分担は責任境界やグループ化された担当領域として見え、表現は対象読者ごとのビューやビューポイントとして見えるようにしてください。

中心の「アーキテクチャ」ノードからは、補助的な分岐として 3 つの小さなノードを作成してください: アーキテクチャ原則、アーキテクチャ制約、意思決定フレームワーク。これらは「アーキテクチャの観点」よりも視覚的に従属的に見えるようにし、主軸は観点であることを明確にしてください。重要なメッセージは、観点がチームの思考を整理し、原則・制約・意思決定の枠組みが最終設計を支える、というものです。

左から右、または上から下へ向かう微かな流れを加えてください: アーキテクチャ -> 観点 -> 理解と推論 -> 支援的ガイダンス -> 設計判断

代替テキスト: 「アーキテクチャズームマップ。構造、運用、戦略、責任分担、表現の観点で整理され、原則、制約、意思決定フレームワークが支援的なガイダンスとして関連づけられている図」

Do:
- 図をきれいで読みやすく、編集向けのインフォグラフィックとして保つ
- 推論レンズとガイダンス層の違いを強調する
- 構造を一目でスキャンしやすくする
- アーキテクチャが単一のマスターダイアグラムではなく、補完的なレンズの集合であることを視覚的に示す
- ラベルを簡潔で、公開用ドキュメント向けに保つ

Do not:
- 図をデプロイメント図やクラウドトポロジーに変える
- 組織図や製品アーキテクチャマップのように見せる
- キャンバスを過剰な詳細や小さすぎる文字で埋め尽くす
- 5 つの観点が互いに同義であるかのように見せる
- 補助的なガイダンスノードを主な整理軸のように見せる
- ロゴやベンダー固有のスタイルを使う

Audience: 経験豊富なソフトウェアエンジニア、アーキテクト、技術リーダー、プラットフォームエンジニア、エンジニアリングマネージャー
