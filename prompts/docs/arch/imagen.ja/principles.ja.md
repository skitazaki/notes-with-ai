# 画像生成プロンプト - アーキテクチャ原則

次の内容で、出版品質の概念図を作成してください。

タイトル:

"アーキテクチャ原則"

サブタイトル: 目的から持続的な意思決定ガイダンスへ。

目的:

事業と技術の目的がどのようにアーキテクチャ原則へと変わり、その原則が意思決定の枠組み、具体的なアーキテクチャ判断、そして最終的なビューと実装にどう影響するかを示してください。
この図は、原則が長期にわたって複数の判断を支える「持続的なガイダンス」であることを伝えるものにしてください。

スタイル:

- クリーンで技術的なインフォグラフィック
- ベクター風の編集用レイアウト
- 明るい背景
- プロフェッショナルなドキュメント調
- 読みやすいラベル
- 16:9 のアスペクト比
- ベンダーニュートラルで概念中心
- ロゴや製品ブランドは使用しない

構成:

左から右へ進む明確なプロセスフローを作成し、5つの段階を矢印で接続してください。

1. 事業と技術の目的
2. アーキテクチャ原則
3. 意思決定の枠組み
4. アーキテクチャ判断
5. ビューと実装

各段階は四角いパネルまたは丸みを帯びたノードで表し、中間の「アーキテクチャ原則」を、戦略的な意図と実務的な意思決定の橋渡しとして視覚的に強調してください。
この図は、デプロイメント図や技術トポロジーではなく、推論の流れとして理解できるようにしてください。

各段階の下または中に補足ラベルを付け、意味が明確になるようにしてください。

- 目的: 戦略的な意図、優先事項、制約
- 原則: 持続的な選好と既定のガイダンス
- 意思決定の枠組み: トレードオフ分析、根拠、例外
- アーキテクチャ判断: 文脈に応じた具体的な選択
- ビューと実装: 判断の伝達と実行

図全体では、目的が再利用可能なアーキテクチャ上のガイダンスを生み、チームが代替案を評価し、繰り返し判断を下す際の出発点と根拠を形作ることが伝わるようにしてください。

中心メッセージ:

アーキテクチャ原則は、意図を持続的なガイダンスへ変換する。
判断そのものを置き換えるものではなく、既定値、根拠の負担、そして繰り返される多くの判断の一貫性を形づくる。

以下を守ってください。

- 視覚的な階層を明確でバランスの良いものにする
- 推論の流れを一目で追えるようにする
- 原則が多くの判断に再利用されるガイダンスであることを強調する
- モダンで技術文書に適した雰囲気を保つ
- ラベルは簡潔で正確にする

以下は避けてください。

- デプロイメント図やシステム構成図にしない
- ロゴ、製品アイコン、ベンダーブランディングを入れない
- 細かすぎるテキストや過密な情報を避ける
- 原則が絶対的なルールや単一の技術選定であるように見せない
- ただの一般的なワークフロー図として扱わない

対象読者:

- ソフトウェアアーキテクト
- エンジニアリングリーダー
- プラットフォームおよびシステム設計者
- 繰り返し設計判断を行う技術チーム
