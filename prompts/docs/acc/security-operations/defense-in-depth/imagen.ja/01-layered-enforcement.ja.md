# 画像生成プロンプト — 多層の適用

**多層の適用** というタイトルの、1600 × 900 ピクセルの高品質な技術イラストを作成してください。

## 目的

「多層防御アーキテクチャ」ページの「多層の適用」セクション向けに概念図を作成してください。高リスクのアクセス要求が複数の補完的な制御領域で保護されることを示します。認可を含む単一統制だけでは十分ではなく、組み合わせた層が影響範囲を抑え、検知と封じ込めを可能にすることを中心メッセージにしてください。

## 構図

穏やかな一本の左から右への要求経路を使います。最も左に小さな **高リスク要求**、最も右に小さな **保護対象の操作** のカードを配置してください。その間に、同じ視覚的強調度で等間隔の角丸ゲートを必ず次の順序で6つ配置します。

1. **本人確認と MFA**
2. **デバイス / ワークロード信頼**
3. **ネットワークとセッションポリシー**
4. **認可ポリシー**
5. **異常検知とトランザクション監視**
6. **ログ、アラート、封じ込め**

細い実線の方向線だけを使用してください。劇的な漏斗、迷路、攻撃シナリオ、または認可だけを唯一・最終の権限に見せる表現は使わないでください。

経路全体の下に **継続的な監視と対応** とラベル付けした控えめな横長バンドを置いてください。すべてのゲートへ控えめに接続し、前段ゲート側への小さなフィードバック接続を一つ加えます。検知が封じ込めや復旧を起動できることを示し、最終工程ではなく横断統制として表現してください。

## 各ゲートの内容

各ゲートには単純なアイコン一つと短いラベルだけを使い、説明段落は入れないでください。

- 本人確認と MFA: 人またはワークロードの主体と、フィッシング耐性の検証を示す。
- デバイス / ワークロード信頼: デバイス状態、ワークロード証明、実行状態の証拠を評価する。
- ネットワークとセッションポリシー: セグメンテーションまたはセッション条件を示す。境界だけで十分には見せない。
- 認可ポリシー: 要求された操作を文脈に基づいて評価する。許可を拒否より強調しない。
- 異常検知とトランザクション監視: 普段と異なる行動、要求パターン、取引リスクを識別する。
- ログ、アラート、封じ込め: 判断を記録し、アラートを対応または隔離へ結び付ける。

## 視覚スタイル

- 温かみのあるオフホワイト背景の、クリーンで編集的なフラットベクタースタイル。
- 濃紺の文字と輪郭線を基本に、ブルー、ティール、淡いインディゴ、控えめなグリーンを使用する。リスクまたはアラートだけに落ち着いたアンバーを1色使える。
- 通常の記事幅で全ゲートのラベルを読めるようにし、十分な余白、統一した角丸形状・アイコン線幅・細い実線コネクターを用いる。
- ベンダー中立にする。製品名、事業者・標準ロゴ、コンプライアンスバッジ、製品UI、表、実装固有の設定を含めない。
- 16:9 横長、1600 × 900 ピクセル、WebP へ変換可能な高品質ラスターとして出力する。

## 禁止事項

- 攻撃者の移動経路、侵害タイムライン、キルチェーンとして描かないでください。
- 前段ゲートを通過すれば必ず許可されるように描かないでください。どのゲートも拒否、追加認証、封じ込め、停止を行えます。
- ファイアウォール、MFA、認可ポリシーのいずれかだけで完全に保護できるように表現しないでください。
- フードを被った人物、ハッカー、二進数背景、巨大な南京錠、城壁、サーバーラック写真、ネオン調のサイバーパンク、光沢のある3D表現、グラデーション、透かしを使わないでください。
- 長い説明、製品スクリーンショット、実装手順、架空のメトリクス、指定した6ゲートと監視バンド以外の統制を追加しないでください。
