# 画像生成プロンプト — AI エージェントと自律的認可

**AI エージェントと自律的認可** というタイトルの、1536 × 1024 ピクセルの高品質な技術イラストを作成してください。

## 目的

AI エージェントの委譲認可を説明する、自己完結した技術イラストを 1 枚作成してください。他の画像、文書、システム図、参照資料がなくても、この画像単体で内容を理解できるようにしてください。AI エージェントは、利用者の無制限な権限を持つ単なる UI ではなく、制約された委譲権限のもとで実行する Principal であることを示します。エージェントの実行アイデンティティと、委譲や権限を評価する対象となる利用者または業務上の Subject を明確に区別してください。

## 必須レイアウト

次のレイアウトを厳密に維持してください。独立した主体カードの集合ではなく、1 本の主判断経路として表現します。

```text
利用者 / 委譲元
       │
       ▼
AI エージェント
       │
       ▼
ポリシー適用ポイント（PEP）
       │
       ▼
┌────────────────────────────────────────────────────┐
│ ポリシー判断ポイント（PDP）                          │
│                                                      │
│ Principal: エージェントのアイデンティティ            │
│ Subject: 委譲元の利用者または業務上の主体            │
│ タスク範囲                                            │
│ リソースと操作                                        │
│                                                      │
│ [実行文脈]                 [委譲文脈]                 │
│                                                      │
│ ポリシー、承認、有効期限、ツール範囲                  │
└────────────────────────────────────────────────────┘
       │
       ▼
   ◇ 許可するか ◇
      │       │
    許可      拒否
      │       │
      ▼       ▼
ツール /    拒否して記録
対象システム     │
      │          │
      └────┬─────┘
           ▼
         監査ログ
```

上部で、**利用者 / 委譲元** が **境界付き委譲** を **AI エージェント** に渡します。委譲トークンの中では、タスク範囲、有効期限、許可ツールをコンパクトな視覚記号だけで示し、それらの文字ラベルは追加しないでください。

エージェントは自身の資格情報でツール操作を要求します。**ポリシー適用ポイント（PEP）は認可判断を行いません。** PEP は要求を受け止めて PDP へ転送し、PDP の判断結果を適用するだけです。PEP から許可・拒否を判断しないでください。PEP の下や横に、拒否アイコン、拒否ラベル、拒否分岐、その他の副経路を描かないでください。

PDP を画像中央の最も強い焦点にしてください。Principal、Subject、タスク範囲、リソースと操作は、PDP 内の 1 つの共有パネルに、独立した 4 行としてまとめます。Principal と Subject は異なる認可属性であり、別々の主体カードではありません。タスク範囲とリソースと操作を、他のカードへ重複して表示しないでください。

**実行文脈** と **委譲文脈** は、PDP 内の共有パネルの下に置く 2 つの小さな補助カードです。実行文脈は Principal に、委譲文脈は Subject に視覚的に対応させますが、PDP へ流れ込む独立入力としては描かないでください。

許可・拒否の分岐は、PDP の後にある **許可するか** からだけ開始します。拒否は直接かつ 1 本だけ **拒否して記録** へ進めます。許可は直接 **ツール / 対象システム** へ進めます。両方の結果を最終的に **監査ログ** へ合流させてください。

## 視覚的な優先順位とスタイル

- PDP と Principal と Subject の区別を画像の中心的な洞察として扱ってください。
- UI スクリーンショットではなく、クリーンな編集系フラットベクタースタイルにしてください。
- 温かみのあるオフホワイト背景、濃紺の文字と輪郭線、控えめなブルーとティールの面、判断状態だけに使う落ち着いたアンバーまたはコーラルのアクセント 1 色を使用してください。
- 統一された角丸カード、実線接続、均一な線幅、最小限の補助アイコン、十分な余白を使用してください。
- 暗号方式の図にせず、境界付き委譲を視覚的に分かるようにしてください。
- 標準的な閲覧サイズで全ラベルを判読でき、矢印が交差せず追いやすいようにしてください。
- ベンダー中立とし、ロゴ、クラウド事業者のブランド、製品 UI、特定標準の名前を使用しないでください。
- 1536 × 1024 ピクセル、3:2 横長、WebP への変換に適した高品質ラスターとして出力してください。

## 画像内で使用する文字

次の文字だけを一字一句そのまま使用してください。

- **AI エージェントと自律的認可**
- **利用者 / 委譲元**
- **AI エージェント**
- **境界付き委譲**
- **ポリシー適用ポイント（PEP）**
- **ポリシー判断ポイント（PDP）**
- **Principal: エージェントのアイデンティティ**
- **Subject: 委譲元の利用者または業務上の主体**
- **実行文脈**
- **委譲文脈**
- **タスク範囲**
- **リソースと操作**
- **ポリシー、承認、有効期限、ツール範囲**
- **許可するか**
- **許可**
- **拒否**
- **ツール / 対象システム**
- **拒否して記録**
- **監査ログ**

画像内に、サブタイトル、説明文、上記以外の略語展開、製品名、標準名、その他の文字を追加しないでください。

## 禁止事項

- AI エージェントが利用者本人である、または利用者の無制限な権限を継承するように表現しないでください。
- Principal と Subject を独立した 2 つの主体カードや独立した 2 つのパネルとして描かないでください。1 つの共有パネル内の別々の行として表示してください。
- PEP と PDP を経由せず、AI エージェントからツールへ直接つながる経路を描かないでください。
- PEP から許可・拒否の判断、拒否アイコン、拒否分岐を描かないでください。
- 許可された操作だけを監査可能にしないでください。拒否された操作も監査ログへ到達させてください。
- 脅威一覧、承認ワークフロー、ロール行列、システムアーキテクチャマップ、マルチエージェントのオーケストレーション図にしないでください。
- 小さな文字、長いキャプション、交差線、点線、過剰な矢印、光沢 3D、写実的な人物、サイバーパンク表現、ロゴ、透かし、UI スクリーンショットを使用しないでください。
