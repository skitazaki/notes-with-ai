# タイトル

**現代的なデータプラットフォームにおける MDM**

## サブタイトル

**マスタ化されたエンティティデータが、業務システム、分析基盤、現代的な統合パターンをどのようにつなぐか**

# 目的

MDM が、業務アプリケーション、API、イベント駆動統合、CDC パイプライン、データウェアハウス、データレイク、レイクハウスなどを含む現代的なエンタープライズアーキテクチャの中で、どのような役割を果たすかを示してください。

図全体を通して、MDM が単独の保存基盤ではなく、より大きなシステム全体の中でアイデンティティとガバナンスを調整するレイヤーであることが理解できるようにしてください。

# スタイル

- クリーンなアーキテクチャドキュメント向け図版
- シャープなベクターブロック、コネクタ、オーバーレイ
- 明るい背景
- 落ち着いたエンタープライズ向け配色
- 記事幅で読めるラベル
- 16:9
- ベンダー中立で出版向け品質
- インフラ図の細部ではなく概念の説明を重視

# 構図

図全体を、横方向の3つの帯またはゾーンに分けて構成してください。

- 業務システム
- 統合および MDM 制御レイヤー
- 分析および活用プラットフォーム

業務システムのゾーンには、以下のようなシステムを配置してください。

- 顧客管理
- 基幹業務
- 人事
- 調達または供給管理
- サポート

中央のゾーンには、以下の要素を配置してください。

- MDM ハブまたはマスタ化エンティティサービス
- アイデンティティ解決と照合
- スチュワードシップのワークフロー
- CDC またはイベントストリーム
- API または統合サービス

分析と活用のゾーンには、以下の要素を配置してください。

- データウェアハウス
- データレイクまたはレイクハウス
- BI またはセマンティックレイヤー
- AI または機械学習の利用者
- 業務 API または下流アプリケーション

複数の連携パターンが同時に存在することを、読みやすさを保ちながら矢印で表現してください。

- ソースレコードが MDM レイヤーへ入る流れ
- マスタ化されたエンティティが選択された業務システムへ戻される流れ
- イベントまたは CDC が下流の分析基盤へ流れる流れ
- 利用側が MDM レイヤーからマスタ ID や参照関係を利用する流れ

簡潔な注記として、次の概念が伝わるようにしてください。

- 権威あるエンティティアイデンティティ
- ソースシステム由来のリネージ
- 同期と伝播
- ガバナンスとスチュワードシップの統制

# 中心メッセージ

MDM は、データウェアハウス、データレイク、API、イベントストリームを置き換えるものではありません。

それらのあいだで、中核エンティティのアイデンティティを安定化させるための調整レイヤーであることを示してください。

## 小さなキャプション

**業務システムがエンティティを作り更新し、MDM がそれらを整合させ、各種プラットフォームと利用者が整備済みアイデンティティを再利用する**

# 必須条件

- 業務、制御、分析の3つのゾーンの分離を視覚的に明確にする
- 1つのアーキテクチャ内で複数の統合パターンが共存することを示す
- 生のインフラ詳細ではなく、アイデンティティ、リネージ、同期を強調する
- クラウドネイティブ環境とハイブリッド環境の両方で成立しそうな構図にする
- MDM レイヤーは保存先の中心ではなく、調整の中心として見せる

# 禁止事項

- すべての接続を描き込んだ密なネットワーク図にしない
- 単一の巨大データベースが業務システムを置き換えるように描かない
- データウェアハウスやレイクハウスを MDM と混同させない
- ベンダーロゴ、製品 UI、ブランド付きクラウドアイコンを使わない
- 分析基盤だけを強調しすぎて、業務統合の文脈を弱めない

# 追加制約

- 画像内の文字は日本語のみとし、英語は含めない
- システム名、ゾーン名、注記、キャプションもすべて日本語で表現する
- 文字量が多くなる場合は、英語ラベルを残さず、日本語の短い表現へ置き換える
- 必要であれば文字量を減らし、構図と矢印で関係性を伝える
