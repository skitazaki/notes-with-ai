# Image Generation Prompt - MDM Integration with Modern Platforms

Create a publication-quality architecture illustration titled:

"MDM in Modern Data Platforms"

Subtitle: How mastered entity data connects operational systems, analytical platforms, and modern integration patterns.

Purpose:

Show how MDM fits into a modern enterprise architecture that includes operational applications, APIs, event-driven integration, CDC pipelines, and analytical platforms such as warehouses, data lakes, or lakehouses.
The image should help readers understand that MDM is an identity and governance coordination layer within a broader system architecture.

Style:

- clean architecture documentation graphic
- crisp vector blocks, connectors, and overlays
- light background
- restrained enterprise palette
- readable labels at article width
- 16:9 aspect ratio
- vendor-neutral and publication-ready
- concept-first, not infrastructure-diagram clutter

Composition:

Arrange the figure in three horizontal bands or zones:

- Operational Systems
- Integration and MDM Control Layer
- Analytical and Consumption Platforms

In the operational zone, show systems such as:

- CRM
- ERP
- HR
- SCM or Procurement
- Customer Support

In the middle zone, show:

- MDM Hub or Mastered Entity Service
- Identity Resolution and Matching
- Stewardship Workflow
- CDC or Event Streams
- APIs or Integration Services

In the analytical and consumption zone, show:

- Data Warehouse
- Data Lake or Lakehouse
- BI or Semantic Layer
- AI or ML Consumers
- Operational APIs or downstream applications

Use arrows to show multiple patterns at once, but keep them legible:

- source records entering the MDM layer
- mastered entities published back to selected operational systems
- events or CDC feeding downstream analytical platforms
- consumers reading mastered identifiers and reference relationships from the MDM layer

Add a few concise callouts for concepts such as:

- authoritative entity identity
- source-system lineage
- synchronization and propagation
- governance and stewardship controls

Central message:

MDM is not a replacement for warehouses, lakes, APIs, or event streams.
It is the coordination layer that stabilizes core entity identity across them.

Small caption:

"Operational systems create and change entities. MDM reconciles them. Platforms and consumers reuse the mastered identity."

Do:

- make the separation between operational, control, and analytical zones visually clear
- show that multiple integration patterns coexist in one architecture
- emphasize identity, lineage, and synchronization rather than raw infrastructure detail
- keep the architecture credible for cloud-native and hybrid enterprise environments
- make the MDM layer central to coordination, not central to all storage

Do not:

- turn the image into a dense network map with every connection shown
- depict a single giant database replacing operational systems
- confuse the warehouse or lakehouse with the MDM function
- use vendor logos, product UI, or branded cloud icons
- overemphasize analytics at the expense of operational integration

Audience:

- enterprise architects
- solution architects
- data platform engineers
- integration engineers
- governance and metadata practitioners
