# 画像生成プロンプト - データ中心の多層防御

英語版の `data-centric-defense-in-depth.png` を入力画像として使用し、構図、階層、配色、各レイヤーの位置、監視・検知を示す横断要素、余白を維持したまま、日本語版を作成してください。

画像内のタイトルは正確に次のとおりとします。

`データ中心の多層防御`

出力：

- 16:9
- 1600 × 900 ピクセル程度
- WebP へ変換可能な高品質ラスター画像

目的：

データセキュリティハブの最初の Mermaid 図を置き換えます。データが存在・移動する場所を問わず多層の保護が必要であり、監視と検知がすべての防御層を横断することを示してください。中心メッセージは、1 つのシステム境界だけでなく、システムと境界を越えてデータを守ることです。

テキストの置き換え：

- `Data-Centric Defense in Depth` -> `データ中心の多層防御`
- `Data` -> `データ`
- `at rest, in transit, and in use` -> `保存時・転送時・使用時`
- `Protection controls` -> `保護統制`
- `encryption, masking, tokenization` -> `暗号化、マスキング、トークン化`
- `Access & policy controls` -> `アクセスとポリシーの統制`
- `least privilege, isolation, egress` -> `最小権限、分離、持ち出し制御`
- `Platform & workload controls` -> `プラットフォームとワークロードの統制`
- `secure processing, credentials, backups` -> `安全な処理、認証情報、バックアップ`
- `Network & environment controls` -> `ネットワークと環境の統制`
- `boundaries, segmentation, secure transport` -> `境界、セグメンテーション、安全な転送`
- `Monitoring & detection` -> `監視と検知`
- `audit trails, anomalies, extraction signals` -> `監査証跡、異常、抽出シグナル`
- `Protect data across systems and boundaries—not merely one perimeter.` -> `1 つの境界だけでなく、システムと境界を越えてデータを守る。`

制約：

- 指定した日本語を正確かつ読みやすく描画してください。
- `データ` を最も明確な焦点としてください。
- `データ` の下に、保護統制、アクセスとポリシーの統制、プラットフォームとワークロードの統制、ネットワークと環境の統制の4層を、この順序で配置してください。
- `監視と検知` は4つの防御層すべてを横断する要素として表現してください。独立した最終工程にはしないでください。
- レイヤーを順番に実行するワークフローとして描かないでください。
- 英語版からレイアウト、要素数、視覚的階層、配色を変更しないでください。
- 新しい説明文、製品名、ベンダーロゴ、コンプライアンスバッジを追加しないでください。
- 南京錠、巨大な盾、ハッカー、フードを被った人物、二進数背景、サーバーラック写真、地球、クラウド事業者ロゴなど、一般的なサイバーセキュリティのストック表現を使わないでください。
- 3D 表現、グラデーション、過剰な影、透かしを追加しないでください。
