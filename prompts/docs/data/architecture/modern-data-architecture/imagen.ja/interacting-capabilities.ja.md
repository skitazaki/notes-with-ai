# 画像生成プロンプト - モダンデータアーキテクチャの能力

正確に **モダンデータアーキテクチャ** というタイトルを付けた、1672 × 941 ピクセル（16:9）の洗練された技術インフォグラフィックを作成してください。

伝える考えは一つに絞ります。モダンなデータ環境は、一つの必須パイプラインや一つの中央技術ではなく、相互作用する能力のグラフです。多様なデータソース、移動手段、ストレージと処理の能力、提供インターフェース、利用者が、共通の統制のもとで複数の経路を形成することを示してください。

## 構成

六つの主要領域から成る、余白を十分に確保した左から右への能力グラフを使用してください。**データソース**、**移動**、**提供**、**利用者**を主水平軸上に置きます。**移動**と**提供**の間では、二つの並行する能力領域として、**ストレージ**を上、**処理**を下に縦に配置してください。

```text
                              ┌→ ストレージ ────┐
データソース → 移動 ─────────┤        ↕         ├→ 提供 → 利用者
                              └→ 処理 ──────────┘
```

このテキスト図をそのまま再現しないでください。抑制された矢印と明確なグループ化を用い、バランスのよいエディトリアル図として構成してください。上段では、データがストレージへ移動してから提供される経路を示します。下段では、データが処理へ直接移動してから提供される経路を示し、ストリーミングなどがストレージを経由しない場合があることを一目で理解できるようにしてください。**ストレージ**と**処理**の縦方向の双方向関係により、処理がストレージから読み取る場合と書き込む場合の両方を示し、一つの逐次パイプラインとして描かないでください。

六つの領域には、以下の見出しと内容を正確に表示してください。

### 1. データソース

**アプリケーション · SaaS · ファイル · イベント · 外部データ**

単独のデータベースアイコンではなく、複数のデータ生成元を表す簡潔なシンボル群を使用してください。

### 2. 移動

**バッチ · API · CDC · メッセージング · ストリーミング**

方向性のある交換またはルーティングを表すシンボルを使用してください。

### 3. ストレージ

**オブジェクトストレージ · ウェアハウス · レイクハウス · 特化型ストア**

ベンダー製品を描かず、複数の用途別ストアを示すグループ化されたストレージシンボルを使用してください。

### 4. 処理

**バッチ処理 · ストリーム処理 · オーケストレーション**

変換または協調された処理を表すシンボルを使用してください。

### 5. 提供

**SQL · セマンティック層 · API · 検索 · 特徴量 · データプロダクト**

インターフェースまたはアクセス層を表すシンボルを使用してください。

### 6. 利用者

**BI · アプリケーション · ML · 生成 AI**

利用形態または成果を表す簡潔なシンボル群を使用してください。

## 必須の関係

次の主要な関係だけを示してください。

- **データソース → 移動**
- **移動 → ストレージ**
- **移動 → 処理**
- **ストレージ ↔ 処理**
- **ストレージ → 提供**
- **処理 → 提供**
- **提供 → 利用者**

**ストレージ**を**処理**の真上に置き、縦方向の双方向関係を明確に区別してください。**移動**から両領域へ分岐し、両領域から**提供**へ再合流させてください。読者がストレージを経由しない経路を認識できるように、下段の **移動 → 処理 → 提供** を視覚的に連続させてください。複数の有効な経路があることを示しながら、図全体を容易に読み取れる状態に保ってください。上記にない矢印は追加しないでください。

## 横断的な能力

**移動**、**ストレージ**、**処理**、**提供**の下に、視覚的に控えめな一つの連続レイヤーを配置してください。レイヤーには正確に **横断的な能力** というラベルを付け、次の用語だけを表示してください。

**メタデータ · 信頼性 · リネージ · セキュリティ · ガバナンス · 可観測性**

共通の下地を用いて、これらの能力が中央の四領域すべてに適用されることを示してください。逐次処理の一段階、外周の個別コールアウト、六つの独立した統制ボックスとして表現しないでください。
