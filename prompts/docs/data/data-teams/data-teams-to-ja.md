# 「Data Teams」日本語版の作成

あなたはデジタルテクノロジーの専門家であり、公開技術ドキュメントを作成するプロフェッショナルです。正確性と概念上の境界を維持しながら、自然で読みやすい日本語の文書を作成してください。

翻訳対象のファイルは以下のパスにあります。

`content/docs/data/teams/_index.md`

日本語版は同じフォルダに `_index.ja.md` として保存してください。
元の文書構造とメタデータ（日付、タイトル、重み付け、`prev`、`next` など）を保持してください。

翻訳方針:

- 文末はですます調で統一してください。
- タイトルは「データチーム」としてください。
- 各セクションの見出しは自然な日本語にしてください。英語の専門用語を残す必要がある場合は、初出時に日本語のあとへカッコ書きで補足してください。
- 表、箇条書き、強調、リンク先パス、Markdown の構造を維持してください。
- 英語の語順をそのまま移す直訳は避け、公開ドキュメントとして明快な日本語にしてください。
- 概念の説明を省略せず、原文と同程度の情報量を維持してください。
- ベンダー寄りの言い換え、実装手順、誇張した表現を加えないでください。

このページで最も重要な点は、次の二つのパターンを曖昧にしないことです。

- **Platform-enabled centralization** は、**共通プラットフォーム**によって強化された中央集権の組織モデルです。データ機能全体の主要な説明責任は中央のデータ組織に残ります。
- **Domain data products** は、各事業ドメインが他の利用者に提供するデータプロダクトの成果に責任を持つ組織モデルです。セルフサービス型プラットフォームとフェデレーテッドガバナンスはこれを支援しますが、各プロダクトの提供を中央で指揮するものではありません。

後者では、データプロダクト間の公開、発見、利用、組み合わせ、契約、標準化された意味、および相互運用性を明確に説明してください。単に人員を分散配置するモデルとして訳さないでください。

用語は以下の規則を優先してください。

- Data Teams -> データチーム
- data work -> データ業務
- Centralized -> 中央集権
- Embedded -> 事業組み込み（事業ドメインに埋め込まれたモデル）
- Platform-enabled centralization -> 共通プラットフォーム
- Domain data products -> ドメイン・データプロダクト
- central data organization -> 中央データ組織
- business domain -> 事業ドメイン
- domain ownership -> ドメインによる所有
- platform enablement -> プラットフォームによる支援
- shared platform services -> 共有プラットフォーム機能
- self-service platform -> セルフサービス型プラットフォーム
- data product -> データプロダクト
- data-product outcome -> データプロダクトの成果
- consumer-facing -> 利用者向け
- federated governance -> フェデレーテッドガバナンス（連邦型ガバナンス）
- governance -> ガバナンス
- interoperability -> 相互運用性
- shared semantics -> 標準化された意味
- data contract -> データ契約
- publication -> 公開
- discovery -> 発見
- consumption -> 利用
- composition -> 組み合わせ
- accountability -> 説明責任
- ownership -> 所有責任
- autonomy -> 自律性

特に、**accountability** と **ownership** を単純に同一視しないでください。文脈に応じて「説明責任」「所有責任」「責任を負う」などを使い分け、誰が成果に責任を持つかという原文の意味を維持してください。

原文が、四つのパターンを成熟度の順序ではなく、組織の状況に応じた選択肢として示していることを保ってください。分散化、データメッシュ、AI を必然的な到達点として表現しないでください。
