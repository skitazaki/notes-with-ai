# Image Generation Prompt - Data Hero Image

Create a publication-quality conceptual hero illustration titled:

"Data as a Strategic Asset"

Subtitle: Four layers that turn data into value while preserving trust, control, and operational coherence.

Purpose:

Introduce the Data section as a high-level model of the data domain.
The image should show that data is not just collected and stored. It becomes a strategic asset when organizations connect four layers into one operating model:

- Source Layer
- Enablement Layer
- Value Layer
- Control Layer

The figure should make clear that value creation depends on engineering and architecture foundations, and that governance, security, and privacy are embedded across the system rather than added afterward.

Style:

- clean editorial infographic
- modern technical documentation aesthetic
- crisp vector-style shapes
- light background
- restrained professional palette with 5 to 6 coordinated colors
- readable labels at article width
- 16:9 aspect ratio
- suitable for a docs section hero image
- concept-first, not product-marketing style
- vendor-neutral, with no logos or product branding

Composition:

Show three clearly bounded upper zones—Source, Enablement, and Value—with the Control Layer as a continuous lower foundation beneath all three. Make the Enablement Layer visibly wider than Source and Value because it contains both the managed data flow and the capabilities that support it.

Do not treat the three upper zones as equivalent process steps. They are responsibility areas. Show directional movement only in a dedicated data-flow lane inside and between those areas.

Use the following layout hierarchy:

1. **Source Layer:** Show operational systems, devices, APIs, and external feeds converging on **Data Collection**. Data Collection is the only named lifecycle activity inside Source.
2. **Platform Boundary:** Draw a clear vertical boundary between Source and Enablement.
3. **Enablement Layer — data-flow lane:** Place **Data Ingestion** entirely inside Enablement, immediately after the platform boundary. Continue the explicit flow as **Data Ingestion → Raw → Transform → Curate → Trusted**. These are the only boxes that form a left-to-right processing sequence.
4. **Enablement Layer — cross-cutting capability bands:** Place **Data Engineering**, **Data Architecture**, **Data Management**, and **Metadata** as four non-sequential bands, rails, or surrounding capability blocks that span or support the whole Enablement data-flow lane. Do not align each capability one-to-one with Ingestion, Raw, Transform, Curate, or Trusted. Do not put arrows between these capability labels.
5. **Value Layer:** After Trusted, show outcomes such as Analytics, Insights, AI / ML Consumption, and Data Sharing. These are value uses, not additional Enablement processing states.
6. **Control Layer:** Place Governance, Security, Privacy, Compliance, and Policy Enforcement in one continuous foundation beneath Source, Enablement, and Value, with subtle upward connections across the lifecycle.

Depict the layers as:

- Source Layer - operational systems, devices, APIs, external feeds, and data collection; do not place data ingestion inside this zone
- Enablement Layer - data ingestion followed by the raw, transform, curate, and trusted flow; supported across the full flow by data engineering, data architecture, data management, metadata, quality, orchestration, and platform foundations
- Value Layer - analytics, insight generation, dashboards, AI or ML consumption, data sharing
- Control Layer - governance, security, privacy, compliance, policy enforcement

Make Source, Enablement, and Value feel like connected responsibility areas, while keeping the processing arrows confined to the dedicated data-flow lane.
Represent the Control Layer as a persistent trust and policy framework beneath all three, with visual connections upward into each stage rather than as an isolated fourth column.

Use directional cues to show that data moves from collection, across the platform boundary, into ingestion, and through Raw, Transform, Curate, and Trusted before reaching value uses.
Use overlays, boundary lines, anchored connectors, or a continuous framing band to show that control mechanisms apply throughout the lifecycle even though the Control Layer sits below the main flow.

Include small but readable visual cues for:

- collection from multiple source types before the platform boundary
- ingestion inside Enablement, accepting data across the platform boundary
- the distinct Raw → Transform → Curate → Trusted data flow
- engineering, architecture, management, and metadata spanning that flow without appearing to be its stages
- metadata and discoverability
- analytics and sharing outcomes
- governance and security guardrails

Central message:

Data becomes a strategic asset when organizations align collection, reliable ingestion, enablement, value creation, and control into one coherent operating model.

Small caption:

"Value is created through layered enablement. Trust is sustained through continuous control."

Do:

- make the four layers immediately legible as a single integrated model
- keep Data Collection inside Source and Data Ingestion entirely inside Enablement, separated by a visible platform boundary
- distinguish the sequential Raw → Transform → Curate → Trusted flow from the non-sequential Enablement capabilities that support it
- make the left-to-right dependency between Source, Enablement, and Value immediately clear
- emphasize that value depends on strong enablement foundations
- show control as cross-cutting and continuous even when it is drawn beneath the other layers
- keep the visual balance between business value and operational rigor
- use abstract but recognizable data-system motifs rather than literal product UIs

Do not:

- turn the image into a dense architecture diagram with many tiny components
- place Data Ingestion inside Source, merge Collection and Ingestion, or imply that a landing zone is a source or collection method
- arrange Data Engineering, Data Architecture, Data Management, or Metadata as consecutive process stages, align them one-to-one with Raw, Transform, Curate, or Trusted, or connect those capability labels with process arrows
- depict control as an afterthought, a separate disconnected function, or merely a final downstream step
- imply that analytics alone defines the data domain
- overload the image with long labels or excessive text
- use vendor logos, cloud badges, or decorative stock-business imagery

Audience:

- technology leaders
- enterprise and solution architects
- data architects and data engineers
- analytics and governance practitioners
- senior software engineers
