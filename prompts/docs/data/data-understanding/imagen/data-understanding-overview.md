# Image Generation Prompt — Data Understanding

Create a polished 1672 × 941 pixels (16:9) technical infographic titled **Data Understanding**.

Communicate one clear idea: practitioners investigate unfamiliar data through complementary, iterative activities to build a reliable model of its meaning, structure, behavior, context, and limitations. Emphasize the investigative work rather than the separate conceptual dimensions of data understanding.

## Composition

Use a left-to-right composition with three main areas:

**Unfamiliar Data → Understanding Activities → Reliable model of the data**

The center must receive the greatest visual emphasis. Use one simple arrow between each main area, but do not present the activities as a sequence.

### 1. Unfamiliar Data

Create a narrow left panel labeled **Unfamiliar Data**, with the subtitle **Different formats, unknown meaning**. Show four compact examples with small, realistic schema or value snippets:

- **Database Table**
- **CSV / Tabular**
- **JSON Document**
- **Event / Log Stream**

Make the data look technically accessible but semantically unclear.

### 2. Understanding Activities

Create a large center panel labeled **Understanding Activities**. Arrange six equally weighted cards in a balanced 2 × 3 grid:

- **Inspect Schema** — table or schema with a magnifying glass; columns and types, keys and constraints, indexes and partitions, nested structures
- **Profile Values** — histogram with compact statistics; distributions, nulls, cardinality, uniqueness, outliers
- **Discover Relationships** — related tables or nodes; candidate keys, joins, foreign keys, correlations, related datasets
- **Interpret Semantics** — tag, annotation, or glossary; business meaning, units, formats, code values, terminology
- **Trace Context & Lineage** — source-to-transformation-to-dataset path; source systems, transformations, provenance, freshness, frequency
- **Validate Assumptions** — domain expert, document, and checkmark; domain knowledge, documentation, subject-matter experts, data quality checks

Do not number the cards or connect them as pipeline stages. If needed, use no more than two subtle visual cues to suggest movement between activities.

Add a compact footer callout inside the center panel:

**Iterative by nature**<br>
**Move between activities as new insights emerge.**

### 3. Reliable Model and Its Uses

Create a distinct right panel headed exactly **Reliable model of the data**. Show the accumulated knowledge in six concise groups:

- **Meaningful columns** — descriptions, units, definitions, valid values
- **Keys & relationships** — keys, joins, cardinality, links
- **Statistical summaries** — distributions, nulls, outliers, trends
- **Business semantics** — code meanings, domain terminology
- **Lineage & context** — sources, transformations, freshness, ownership
- **Known assumptions & limits** — data quality, issues, limitations, risks

Close the panel with this exact summary:

**Meaning • Structure • Behavior • Context • Limitations**

Below it, place four small destination cards in one row:

- **Engineering** — pipelines, models, contracts, quality
- **Analytics** — metrics, reports, dashboards, insights
- **ML** — features, labels, training data, monitoring
- **AI** — RAG, agents, applications, workflows

Connect the reliable model to these cards with a single downward, one-way relationship. Make it clear that they are downstream consumers, not part of the investigation itself.

## Visual Direction

Match the established Notes with AI illustration style: solid opaque white background, large dark-navy title, crisp sans-serif typography, flat vector graphics, thin consistent outlines, simple technical icons, subtle pale fills, restrained blue, green, teal, orange, and purple accents, generous whitespace, strong alignment, and minimal shadows. Keep the composition legible at documentation-column width.

Render every specified heading and card label exactly once and exactly as written. Supporting examples may be shortened when necessary for legibility, but do not introduce new concepts.

Do not add numbered activities, sequential step indicators, arrows between every activity, circular process diagrams, a second **Data Understanding** heading, **Dimensions of Data Understanding** terminology, upward arrows from downstream uses, vendor or product logos, robots, glowing brains, decorative AI imagery, watermarks, photorealism, 3D graphics, gradients, dense prose, or visually busy backgrounds.
