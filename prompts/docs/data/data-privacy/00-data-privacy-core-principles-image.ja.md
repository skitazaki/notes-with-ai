# 画像生成プロンプト — プライバシーの主要原則

**データプライバシー** ドキュメントハブの **主要なプライバシー原則** セクション向けに、公開品質の概念図を作成してください。

目的:

7つのプライバシー原則を、孤立したチェックリストではなく、ひとつの接続されたモデルとして理解できるようにします。この図では、情報を収集するかどうかの判断から削除に至るまで、データライフサイクル全体を通じて、それらの原則が意思決定を導くことを示してください。

想定読者:

- テクノロジーリーダー、アーキテクト、データプラットフォームエンジニア、ガバナンス実務者
- データシステムを理解しているが、必ずしもプライバシーの専門家ではないシニアエンジニア

中心メッセージ:

責任あるデータ利用は、明確な目的から始まり、必要な情報だけに限定し、処理を理解可能にし、本人の意味ある関与を可能にし、責任あるオーナーを割り当て、保持期間を制限し、設計とデフォルト設定の段階からプライバシーを組み込みます。

必須の概念:

次の7つの原則を、以下の正確なラベルと短い補足フレーズで表現してください。

- **目的の明確化** — 明確で特定された目的のために利用する
- **データ最小化** — 必要なデータだけを収集・利用する
- **透明性** — データの利用方法を分かりやすく説明する
- **説明責任** — 責任者を定め、証跡を残す
- **本人の関与** — 知る・選ぶ・訂正する機会を提供する
- **保持期間の制限** — 必要な期間だけデータを保持する
- **プライバシー・バイ・デザイン／デフォルト** — システム設計と初期設定にプライバシーを組み込む

構成:

- 中央に **責任あるデータ利用** と明記した、大きくシンプルな中心要素を配置してください。
- その周囲に、7つの原則パネルを、均衡の取れた円形または正七角形に近いパターンで配置してください。各パネルは中心の周囲に均等に分布させ、角度間隔をそろえ、中心からの距離を共通にし、視覚的な占有面積もほぼ同等にしてください。どこか一方向だけが過密または疎に見えてはいけません。読者が所定の順序を追わなくても、すべての原則を一度に見渡せるレイアウトにしてください。
- 各原則パネルを中心要素へ控えめな線または帯で接続し、それぞれが同じ目標に向けた意思決定レンズであることを示してください。
- 次の関係性は、フローチャートにせず、控えめな接続の手がかりで示してください。
  - 目的の明確化は、データ最小化と保持期間の制限に影響を与える
  - 透明性は、本人の関与を支える
  - 説明責任とプライバシー・バイ・デザイン／デフォルトは、他の原則を実現可能にする

視覚的な優先順位:

- 中心メッセージと7つの原則ラベルは、ドキュメント本文の横幅でも読めるようにしてください。
- 補足フレーズは短く、副次的で、可読性を保ってください。段落にはしないでください。
- アイコンは読み取りやすさを高める場合に限って、各原則につき1つの単純な補助アイコンだけを使用してください。目的の明確化にはターゲット、データ最小化には小さなフィルター、透明性には目、説明責任には所有を示すチェックマーク、本人の関与には吹き出し付きの人物、保持期間の制限には時計またはアーカイブ、プライバシー・バイ・デザイン／デフォルトには設計図または設定アイコンを使用します。
- すべての原則に同等の視覚的な重みを与えてください。パネルサイズと隣接パネルとの間隔も一貫させてください。どれか1つの原則が他を置き換えるようには見せないでください。

スタイル:

- 技術ドキュメント向けの、クリーンなエディトリアル・インフォグラフィック
- 鮮明なベクタースタイルの形状、シンプルな幾何学表現、丁寧な余白設計
- 明るい背景と、コントラストが高くアクセシブルなタイポグラフィ
- 中央には濃い青またはティールを使い、7つの原則には協調した落ち着いたアクセントカラーを使う、抑制の効いたプロフェッショナルな配色
- フラットデザイン、またはごく控えめな奥行き表現。光沢のある3Dレンダリングはしないでください。
- ベンダー中立で、時代に左右されず、製品ブランディングを含まないこと
- 16:9 の横長比率

必須事項:

- 7つの原則が、相互に補強し合う完全な概念フレームワークとして感じられるようにしてください
- 画像全体を落ち着きのある、均整の取れた、一目で読み取れるものにしてください
- 外周の余白も対称的に保ち、パネルの輪が中心の周囲に均等に分布して見えるようにしてください
- ラベルは、上記で示した簡潔な日本語表現をそのまま使用してください

禁止事項:

- 高密度な表、チェックリスト型ポスター、法務文書、コンプライアンス認証図、またはシステムアーキテクチャ図にしないでください
- 原則を必須の線形順序や成熟度モデルとして表現しないでください
- 法律、規制、法域固有の用語を過剰に盛り込まないでください
- 極小の文字、ストック写真、ベンダーロゴ、鍵だけでプライバシーを表す比喩、装飾的な監視イメージを使わないでください
- 同意だけ、セキュリティだけ、または何らかの個別コントロールだけでプライバシーと同等であるかのように示さないでください
