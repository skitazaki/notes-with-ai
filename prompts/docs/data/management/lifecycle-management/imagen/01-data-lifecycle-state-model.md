# Image Generation Prompt — Data Lifecycle Management State Model

Create a publication-quality technical infographic titled exactly:

"Data Lifecycle Management"

Output dimensions and format:

- 16:9 aspect ratio
- suitable for display at 1600 × 900 pixels
- clean raster output that can be converted to WebP
- deliver the asset as `lifecycle-management.webp`

Purpose:

Replace the Mermaid state diagram near the start of the Data Lifecycle Management documentation page. Show that a dataset progresses deliberately from creation to controlled retirement. Ownership, access, retention, and evidence apply throughout; make the distinctive decision in each state visually and textually clear instead of repeating the same questions in every card.

Composition:

- Use a centered, left-to-right flow of exactly four equally prominent rounded cards, connected only by three clear rightward arrows.
- Place the title above the flow.
- Use the following card titles and supporting questions exactly, in this order from left to right:
  1. `Created`
     `Define purpose and accountable owner`
     `Set initial access and retention`
     `Record approval to activate`
  2. `Active / Maintained`
     `Confirm current operational need`
     `Monitor quality and dependencies`
     `Review access and retention controls`
  3. `Historical / Archived`
     `Preserve historical or compliance value`
     `Restrict retrieval access`
     `Maintain lineage and retention schedule`
     `Record archival and recoverability`
  4. `Retired / Decommissioned`
     `Verify no remaining purpose, hold, or dependency`
     `Approve final disposition`
     `Close access and delivery paths`
     `Retain closure evidence`
- Add the exact footer caption below the flow:
  `Every transition is owned, evidenced, and defensible.`
- Give each card a small, abstract line icon that supports its state: origin marker for Created, active record for Active / Maintained, archive box for Historical / Archived, and completed record for Retired / Decommissioned. Icons must remain secondary to the text.

Visual hierarchy and style:

- crisp vector-style editorial infographic
- light neutral or warm off-white background with generous whitespace
- dark navy typography; restrained teal, muted blue, and soft gray accents
- progress visually from fresher teal-blue tones at the left to subdued blue-gray tones at the right, without implying loss of governance
- flat two-dimensional shapes, subtle borders, uniform line weight, and minimal shadows
- large, highly legible sans-serif typography that remains readable at documentation-column width
- calm, vendor-neutral, concept-first, and consistent with a modern technical documentation site

Constraints:

- Render every specified label exactly as written, including capitalization, punctuation, slashes, and question marks.
- Show exactly four lifecycle states, exactly three arrows, and one linear left-to-right progression.
- Do not add loops, branches, feedback arrows, additional states, storage tiers, or unlabeled callouts.
- Do not imply that archival is deletion or that retirement occurs automatically.
- Do not add product names, vendor logos, compliance badges, decorative prose, watermarks, people, server photographs, cloud-provider imagery, 3D effects, gradients, or a busy background.
- Avoid tiny text, dense implementation details, generic database-cylinder hero imagery, and excessive icons.
