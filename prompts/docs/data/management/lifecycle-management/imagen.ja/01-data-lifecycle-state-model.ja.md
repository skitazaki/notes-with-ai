# 画像生成プロンプト — データライフサイクル管理の状態モデル

次のタイトルを正確に表示する、高品質な技術インフォグラフィックを作成してください。

"データライフサイクル管理"

出力形式:

- 16:9 のアスペクト比
- 1600 × 900 ピクセルでの表示に適したサイズ
- WebP に変換できる、クリーンなラスター出力
- アセットは `lifecycle-management.ja.webp` として納品する

目的:

データライフサイクル管理のドキュメントページ冒頭にある Mermaid の状態遷移図を置き換えます。データセットが作成から統制された廃止まで意図的に進むことを示してください。所有者、アクセス、保持、証跡はすべての状態に共通します。そのため、すべてのカードで同じ問いを繰り返すのではなく、各状態で特に重要となる判断を、視覚とテキストで明確にしてください。

構成:

- 中央に、同じ重要度の角丸カードを厳密に4枚、左から右へ並べます。カード間は右向き矢印3本だけで接続してください。
- フローの上部にタイトルを配置します。
- 各カードには、次のタイトルと問いを、左から右へこの順序で正確に表示してください。
  1. `Created`
     `利用目的と責任ある所有者を定める`
     `初期のアクセスと保持を定める`
     `有効化の承認を記録する`
  2. `Active / Maintained`
     `現在の業務上の必要性を確認する`
     `品質と依存関係を監視する`
     `アクセスと保持の統制を見直す`
  3. `Historical / Archived`
     `履歴またはコンプライアンス上の価値を保全する`
     `取り出し時のアクセスを制限する`
     `リネージと保持スケジュールを維持する`
     `アーカイブと復元可能性を記録する`
  4. `Retired / Decommissioned`
     `目的、保全義務、依存関係が残っていないことを確認する`
     `最終処分を承認する`
     `アクセスと提供経路を閉じる`
     `終了の証跡を保持する`
- フローの下に、次のキャプションを正確に配置してください。
  `すべての移行には、所有者、証跡、説明可能性が必要です。`
- 各カードに、その状態を補助する抽象的な線画アイコンを小さく添えます。Created は起点マーカー、Active / Maintained は利用中の記録、Historical / Archived はアーカイブ箱、Retired / Decommissioned は完了済みの記録とします。アイコンよりもテキストを目立たせてください。

視覚的な階層とスタイル:

- 明瞭なベクター調のエディトリアルインフォグラフィック
- 余白を十分に取った、明るいニュートラルまたは温かみのあるオフホワイト背景
- 濃紺の文字、抑制したティール、くすんだ青、淡いグレーの配色
- 左側は鮮度を感じるティールブルー、右側は落ち着いたブルーグレーへ緩やかに移行させる。ただし、右へ進むほど統制が弱まるようには見せない
- 平面的な二次元の形、控えめな境界線、均一な線幅、最小限の影
- ドキュメント本文のカラム幅でも読める、大きく明瞭なサンセリフ体
- 落ち着いた、ベンダー中立、概念を中心にした、現代的な技術ドキュメントサイトに合う表現

制約:

- 指定したすべてのラベルを、英数字、日本語、句読点、スラッシュ、疑問符を含めて正確に表示してください。
- ライフサイクルの状態は厳密に4つ、矢印は厳密に3本、左から右への直線的な進行は1つだけにしてください。
- ループ、分岐、フィードバック矢印、追加の状態、ストレージ階層、ラベルのない吹き出しを追加しないでください。
- アーカイブが削除である、または廃止が自動的に起こると誤解させないでください。
- 製品名、ベンダーロゴ、コンプライアンスバッジ、装飾的な文章、透かし、人物、サーバー写真、クラウド事業者を想起させる画像、3D表現、グラデーション、雑然とした背景を追加しないでください。
- 小さすぎる文字、密度の高い実装詳細、汎用的なデータベース円柱の主役画像、過剰なアイコンを避けてください。
