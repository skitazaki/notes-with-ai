# 画像生成プロンプト — MLOps と LLMOps

公開品質の概念図を作成してください。タイトルは「MLOps と LLMOps」です。

目的: モデルシステムに共通する運用ライフサイクルと、大規模言語モデルのアプリケーションによって広がる運用対象を比較できるようにすること。

中心メッセージ: MLOps と LLMOps はどちらも確率的なシステムへライフサイクル規律をもたらします。ただし、LLM 中心のシステムでは、プロンプト、検索、安全性、実行時の構成も運用上の関心事になります。

構成:

- 中央に明確にラベル付けした共通の運用基盤を置き、そこで結び付く2つの並行したライフサイクルループを描く。
- 左の「MLOps」ループは、目的特化の予測モデルのライフサイクルを表す。次の活動を明確に置く。
  - 「学習データと特徴量／データ品質」
  - 「モデル学習と実験追跡」
  - 「モデルレジストリ、リリース、予測品質の監視」
- 右の「LLMOps」ループは、基盤モデルの周囲に組み立てるアプリケーションのライフサイクルを表す。次の活動を明確に置く。
  - 「プロンプトとモデル設定のバージョン管理」
  - 「検索コーパス／インデックスの品質とグラウンディング」
  - 「安全性と出力品質の評価」
  - 「実行時コスト、レイテンシ、人からのフィードバックシグナル」
- 中央の共通運用基盤には、両方のループに適用される段階として「バージョン管理とリリース」「デプロイ」「監視」「評価」「継続的改善」を明示する。
- MLOps は学習済みモデルとそのデータを最適化し、LLMOps はプロンプト、検索、ガードレール、推論時の選択にも振る舞いが依存する、組み立てられたアプリケーションを運用することを、ひと目で区別できるようにする。
- LLMOps の追加要素は孤立したバッジではなくループへの接続された重なりとして描き、実行時の振る舞いに影響して評価へフィードバックされることを示す。

代替構成（2つのループが過密になる場合）:

- 共有する水平ライフサイクルのパイプラインを使い、上に「MLOps」、下に「LLMOps の追加要素」の行を置く。各追加要素は、変更するライフサイクル段階へ接続する。
- または、MLOps のライフサイクルリングを基盤とし、その外側に「アプリケーションの構成と実行時制御」とラベル付けした LLMOps のリングを重ねる。外側のリングは置換ではなく追加であると明瞭にする。

スタイル:

- 精密なエディトリアル・インフォグラフィック
- ベクタースタイルのライフサイクル図
- 明るい背景、明瞭なループ矢印、最小限の文字量
- 協調した2レーンの配色
- 16:9 の横長比率

必須事項: 共通の関心事と固有の関心事を比較しやすくし、数秒で読める単純さを保ち、ツールではなく運用規律を強調すること。

禁止事項: 詳細な CI/CD パイプライン、LLMOps が MLOps を完全に置き換えることを示す表現、ベンダーロゴや製品バッジは使用しないこと。
