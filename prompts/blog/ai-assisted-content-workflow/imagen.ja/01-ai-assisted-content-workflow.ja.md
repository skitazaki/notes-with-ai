# 画像生成プロンプト — AIを活用したコンテンツ制作ワークフロー

## コンセプト

技術ブログ記事の冒頭に掲載する、公開品質のインフォグラフィックを作成してください。個人の著者が ChatGPT、Codex、GitHub Copilot を使い、アイデアから企画、執筆、レビュー、公開、振り返りへ進む流れを説明します。

中心となるメッセージは、3つのツールがそれぞれ主な役割を担いながら、著者が制作を主導し、主張を検証し、公開可否を判断することです。引き継ぎが明確な反復可能なワークフローを示し、後のレビューと読者の反応から企画へ戻るフィードバックループを1つだけ設けてください。

## レイアウト

横長の **16:9 アスペクト比**にしてください。画像生成ツールがピクセル数を必要とする場合のみ、**1600 × 900 ピクセル**を目安として使ってください。ピクセル数は固定条件ではありません。左から右へ進む、同じ幅の5つのステージカードを、十分な間隔を空けて配置します。最上部に正確なタイトル **「AIを活用したコンテンツ制作ワークフロー」** を置き、その直下にサブタイトル **「人が主導する、アイデアから公開までの流れ」** を配置してください。

5つのカードを次の順に並べます。

```text
[1. 企画] → [2. 執筆指示書] → [3. 下書き] → [4. レビュー] → [5. 公開]
      ↑                                                        │
      └──── Gitの履歴と読者の反応を次の企画に生かす ─────────────┘
```

各カードには、次の要素を含めてください。工程1と工程2の企画および執筆指示書の準備は ChatGPT が担当し、工程3で Codex が執筆指示書をもとに記事を下書きします。この役割分担を必ず守り、工程2を Codex の担当として描かないでください。工程2のカードに Codex の名前やアイコンを置かず、ChatGPT を担当ツールとして明記してください。

1. **アイデアを企画する** — ChatGPT が読者、目的、範囲、記事構成の整理を支援します。アイデアは著者、AIアシスタント、または対話から生まれます。
2. **執筆指示書を準備する** — ChatGPT が記事企画を具体的な執筆指示書にまとめ、想定読者、構成、必要な根拠、範囲を記録します。引き継ぎ資料の保存場所として `prompts/` を表示します。
3. **記事を下書きする** — Codex が執筆指示書を `content/` 内の Markdown に反映します。内容の説明に役立つ場合にビジュアルを計画する旨を、小さく添えてください。
4. **合わせてレビューする** — GitHub Copilot が明瞭さや不足点のレビューを支援し、Codex がリポジトリ内のファイルを修正できます。著者は根拠、リンク、メタデータ、ビジュアル、レンダリング後のページを確認します。
5. **公開して学ぶ** — マージ前のプルリクエストチェック、その後の `main` へのマージ、本番ビルドと GitHub Pages への公開を示します。読者の反応と後日のリポジトリレビューを次の企画に生かします。

カードを左から右へ明確な矢印で接続してください。カードの下に、ステージ5からステージ1へ戻るフィードバックの接続を1本だけ描きます。この接続は前進する経路と区別してください。

## 視覚要素

次のラベルを、表記どおり正確に描画してください。

- `AIを活用したコンテンツ制作ワークフロー`
- `人が主導する、アイデアから公開までの流れ`
- `アイデアを企画する`
- `執筆指示書を準備する`
- `記事を下書きする`
- `役立つ場合にビジュアルを計画`
- `合わせてレビューする`
- `公開して学ぶ`
- `ChatGPT`
- `Codex`
- `GitHub Copilot`
- `prompts/`
- `content/`
- `main`
- `GitHub Pages`
- `Gitの履歴と読者の反応を次の企画に生かす`
- 工程2のカード内に担当ツールとして `ChatGPT` を明記する

カード内の補足は短い語句にとどめ、説明文の段落を入れないでください。必要に応じて汎用的で一貫性のある線画アイコンを使い、製品ロゴは使わないでください。前進する5段階と、1本だけの戻り矢印を視覚的に区別してください。

必須の接続は次のとおりです。

```text
アイデアを企画する → 執筆指示書を準備する → 記事を下書きする → 合わせてレビューする → 公開して学ぶ
公開して学ぶ → アイデアを企画する（フィードバックループ）
```

執筆指示書やレビューを迂回する分岐を追加しないでください。画像生成を必須の工程にしないでください。ビジュアルの計画は、執筆ステージ内の条件付きの注記として示します。ChatGPT、Codex、GitHub Copilot の役割を排他的な能力として描かず、上記の主な役割だけを示してください。AIの出力やAIレビューが事実の正しさを保証するように表現しないでください。

## スタイル

- 技術ブログ向けの、整然とした編集用インフォグラフィック。
- 正確なベクター風の図形と文字、十分な余白。
- 品質の序列を示さずに5段階を見分けられる、落ち着いた配色。
- 明るいニュートラルな背景と、読みやすい濃色の文字。
- 一般的な記事幅で表示してもラベルが読める大きさ。
- 縦に長く広がるフローチャートを避け、バランスよくコンパクトに配置。
- 不透明な背景とし、WebP に変換できるラスター画像向けの構成。
- 装飾だけの要素、コントラストを下げるグラデーション、小さな注記、透かし、指定外のテキストを入れない。
