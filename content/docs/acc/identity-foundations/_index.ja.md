アイデンティティ基盤は、人、ワークロード、マシン、サービス、その他の主体をどのように認識・検証・統制して、説明可能なアクセス判断に結び付けるかを示します。

最初に問うべきことは「どのプロトコルを使うか」だけではありません。より根本的には「何をアイデンティティとして扱っているのか」です。人のアイデンティティと非人間のアイデンティティは、共通の制御機能を持ちながらも、別の主体クラスとして扱うべきものです。

## アイデンティティが重要な理由

アイデンティティは説明責任の基盤です。システムに対して、認証、権限、行動、レビューを結び付けられる識別可能な主体を与えます。安定したアイデンティティがなければ、誰または何が行動したのか、どのポリシーが適用されるべきかを明確に答えられません。

アイデンティティは単なるユーザー名やログインフローではありません。対象は、個人、ワークロード、マシン、サービス、デバイス、AI エージェントなど多岐にわたります。信頼を確立しアクセスを制御する仕組みは主体ごとに異なるかもしれませんが、説明責任の問題そのものは同じです。

## アイデンティティの主体

このセクションを整理する最も明快な軸は、識別される主体が何であるかという点です。

### 人のアイデンティティ

人のアイデンティティは、従業員、顧客、パートナー、請負業者、特権管理者などの人間を表します。一般に、アカウントライフサイクル、本人確認、認証、フェデレーション、MFA、プロビジョニングと削除、ガバナンスが含まれます。

人のアイデンティティに関する設計では、単に「ログインできるか」だけでなく、「正しい人に、適切な権限が、適切な条件で、適切な期間だけ付与されているか」が重要です。

この領域は人のアイデンティティとエンタープライズ IAM のトピックで扱われます。そこではライフサイクル制御、アクセスレビュー、フェデレーション、特権アクセス管理が説明されます。

### 非人間のアイデンティティ

非人間のアイデンティティ（non-human identity）は、ワークロード、マシン、デバイス、サービス、その他の自動化された主体を表します。多くの場合、ランタイム ID、ワークロードの証明、短命な認証情報、証明書、鍵、サービス間の信頼などを通じて発行・管理されます。

例として次のようなものがあります。

- コンテナ、VM、サーバーレス実行環境内で動作するワークロード ID
- エンドポイントやインフラコンポーネントを表すマシン ID とデバイス ID
- アプリケーション間アクセスに使うサービス ID
- 自律的または半自律的に動作する AI エージェントの ID

AI エージェントは単なる従来型のサービスアカウントではありません。人間による起動やシステムによる制御がある一方で、行動の帰属、制約、監査が必要になる新しい非人間 ID のクラスです。

## 横断的なアイデンティティの機能

人のアイデンティティと非人間のアイデンティティは、多くの運用上の懸念を共有しています。実際の仕組みは異なっても、以下のような機能は両方に共通しています。

- 認証: 主体がそのアイデンティティを実際に管理・代表していると信頼できるようにすること
- フェデレーション: ドメイン間で信頼を確立し、アイデンティティ情報を交換すること
- プロビジョニングと非プロビジョニング: アイデンティティとそのアクセス関係を作成・削除すること
- 認証情報と秘密情報の管理: ローテーション、失効、更新
- ライフサイクル管理: レビュー、再検証、監査可能性
- 認可: 認証済みの主体に何が許可されるかを決定すること

重要な区別は次のとおりです。人と非人間はアイデンティティの主体を表し、その他の項目はその主体に対して信頼とアクセスを管理するための機能です。

| 人のアイデンティティ                               | 非人間のアイデンティティ                                      |
| -------------------------------------------------- | ------------------------------------------------------------- |
| 人間                                               | ワークロード、マシン、サービス、エージェント                  |
| 従業員と顧客のアカウント                           | ランタイムとインフラのアイデンティティ                        |
| パスワード、パスキー、MFA、セッション制御          | 証明書、鍵、短命な認証情報、証明書と起源の証明（attestation） |
| ユーザー向けの SSO とフェデレーション              | サービス間の信頼とワークロード ID パターン                    |
| プロビジョニング、非プロビジョニング、権限レビュー | 登録、ローテーション、失効、ランタイム信頼                    |
| 人間のライフサイクルとガバナンス                   | マシンとランタイムのライフサイクル管理                        |

比較の目的は包括的な網羅ではなく、概念上の明確さです。どちらにも共通する原則があります。主体を確立し、制御を証明し、信頼を結び、権限を割り当て、時間の経過とともに説明責任を維持することです。

## アイデンティティのライフサイクル

人のアイデンティティと非人間のアイデンティティの両方にライフサイクルの段階がありますが、具体的な仕組みは異なります。

```text
作成 / 登録
      ↓
信頼の確立
      ↓
認証
      ↓
属性 / 権限の紐付け
      ↓
アイデンティティの利用
      ↓
ローテーション / 再検証
      ↓
停止 / 失効 / 削除
```

すべてのアイデンティティがこの順序を完全に同じようにたどるわけではありません。人の業務上の ID は HR やディレクトリのプロビジョニングに左右される一方、ワークロード ID は起動時に発行され、自動的にローテーションされることがあります。共通するのは、アイデンティティは作成され、信頼に紐付けられ、ポリシーの下で使われ、条件が変化したときに失効または再検証されるという点です。

## アイデンティティと認可

アイデンティティと認可は密接に関係しながらも、別の問題です。

- アイデンティティは「誰または何が行動しているか」を答えるものです。
- 認可は「何を許可されているか」を答えるものです。

人のアイデンティティでは、その答えは個人です。非人間のアイデンティティでは、ワークロード、マシン、サービス、エージェントがその対象になります。どちらの場合でも、識別と認可は異なるレイヤーです。アイデンティティは主体を確立し、ポリシーがその主体に対して許可される行動の範囲を決定します。

一般的な関係は次のとおりです。

```text
アイデンティティの主体
      ↓
認証 / 制御の証明
      ↓
属性 / コンテキスト
      ↓
認可ポリシー
      ↓
アクセス判断
      ↓
説明責任 / 監査
```

このため、強力な認証があれば自動的にガバナンスの問題が解決されるわけではありません。安全で説明可能なアクセスを実現するには、ポリシー、ライフサイクル制御、信頼境界、監査可能性が必要です。

## このセクションの位置づけ

このセクションは、続く子トピックを理解するための概念マップです。

- 人のアイデンティティとエンタープライズ IAM は人と企業アクセスの統制を扱います
- SSO とフェデレーションはユーザー向けの信頼とシングルサインオンを説明します
- SCIM とプロビジョニングはライフサイクル同期とアカウントの作成と削除の制御を説明します
- ワークロード、マシン、非人間 ID はランタイム ID、マシン間の信頼、自動化された主体を扱います

これらのトピックを合わせると、アイデンティティは単一の技術領域ではなく、主体を表すパターン、信頼を確立するパターン、ライフサイクルを統制するパターン、そしてその主体をポリシーと説明責任に結び付けるパターンの集合であることが分かります。
