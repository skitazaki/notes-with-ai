テストレベルは、検査する振る舞いの範囲と境界を表します。価値の低いものから高いものへの順位ではなく、相互補完する視点です。

## 局所と境界の検証

単体テストは小さな振る舞いを検査し、通常は高速で原因を絞りやすい失敗を返します。単位は関数、オブジェクト、モジュール、一貫した機能のいずれでもよく、モックフレームワークが定義するものではありません。非公開の実装構造を再現するより、安定した振る舞いを重視します。

統合テストはデータベース、キュー、ファイルシステム、ランタイム、外部サービスなどの実際の境界を越える連携を検証します。シリアライズ、トランザクション、設定、タイミング、障害処理の前提を明らかにします。適切に選んだ少数の統合テストは、多数の分離されたモックでは見えないリスクを発見できます。

契約テストは独立して変更される主体間のインターフェースを検証します。利用側と提供側の結果を使い、システム全体をデプロイせずに互換性のない API やイベントを検出できます。契約にはバージョン、所有者、廃止規則が必要です。

## システムの行程

エンドツーエンドテストは、デプロイされた構成要素を通る代表的な利用者またはシステムの行程を確認します。接続と重要な結果を検証できますが、失敗は遅く診断も困難です。高価値の行程へ絞り、詳細な変化は低いレベルで確認します。

同じ振る舞いをすべてのレベルで反復する必要はありません。重大なリスクを守る、または診断を改善する重複には意味がありますが、偶発的な重複は確信に見合わない保守コストを生みます。

## まとめ

単体、統合、契約、エンドツーエンドテストは異なる問いに答えます。範囲、現実性、速度、診断価値がリスクに最も合う場所で各レベルを使います。
