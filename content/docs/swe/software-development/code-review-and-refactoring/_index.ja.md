コードレビューとリファクタリングは、変更を理解可能に保つための相互補完的なプラクティスです。レビューは提案された変更を共有知識に照らして検討し、リファクタリングは内部構造を改善して将来の変更コストを抑えます。

## 意図とリスクをレビューする

レビューは差分の書式ではなく、問題、制約、期待する振る舞いの理解から始めます。繰り返し可能な機械的検査は自動化し、人は正しさ、境界、失敗モード、セキュリティ、運用性、代替案より単純かどうかへ集中します。

小さな変更はレビュー時間を短くし、見落としたケースを発見しやすくします。作成者は文脈と検証結果を示し、レビュー担当者は修正必須の欠陥と提案を区別します。承認はレビューした証拠ですが、責任が作成者からレビュー担当者へ移るわけではありません。

## 安全にリファクタリングする

リファクタリングは、観測可能な振る舞いを意図的に変えずに内部構造を変えます。命名の明確化、責任の分離、重複の除去、隠れた結合から明示的なインターフェースへの変更などがあります。抽象化を最大化するのではなく、現在の知識と予想される変更に合う構造を目指します。

振る舞いを保つ作業には安全網が必要です。焦点を絞ったテスト、段階的なコミット、静的解析、本番シグナルの比較が判断材料になります。大規模な書き直しは構造変更と振る舞い変更を混在させるため、限定された変換を積み重ねる方が一般に安全です。

レビューはシステム知識も広げますが、唯一の手段にすべきではありません。設計メモ、ペア作業、所有者の交代、読みやすいコードによって、重要な理解が特定のレビュー担当者だけに依存することを防ぎます。

## まとめ

効果的なレビューは限られた人の注意を意図とリスクへ向けます。規律あるリファクタリングは、検証結果と段階的な変更によってシステムの進化可能性を保ちます。
