ツールは、モデル駆動のアプリケーションを外部の情報やアクションへ接続します。ナレッジベースの検索、業務レコードの読み取り、計算の実行、チケットの作成、承認の要求などができます。つまりツールは強力なコンテキストの情報源であると同時に、副作用が発生する境界でもあります。

Model Context Protocol（MCP）は、コンテキストに関わる能力を公開する外部サーバーへ、AI クライアントを接続するための標準プロトコルです。相互運用性を高めますが、アプリケーションレベルの認可、検証、運用上の制御を不要にするものではありません。

## 定義

ツールとは、AI アプリケーションが別システムに境界のある能力を要求するためのインターフェースです。ツールの結果は、モデルまたはワークフローが解釈するコンテキストになります。安全な設計では、入力、戻り値、要求を実行する ID、許可される副作用を明示的な契約として扱います。

MCP は、MCP サーバーを介して能力を AI クライアントへ提供するためのプロトコルモデルの一つです。クライアントとサーバー、実行可能な能力としてのツール、コンテキストデータとしてのリソース、再利用可能な対話テンプレートとしてのプロンプトなどの概念を含みます。これらは統合の発見と一貫した利用を助けますが、組織の信頼ポリシーを定義するものではありません。プロトコルのドキュメントと仕様は、[Model Context Protocol 公式サイト](https://modelcontextprotocol.io/)を参照してください。

## なぜツールが重要か

ツールの利用により、AI アプリケーションは静的なモデル知識を超えられます。ツールは現在の在庫、アカウント状態、統制されたコーパスを検索したり、レビュー用の下書きを提出したりできます。また、モデル出力を現実世界のアクションに変えることもできます。そのため、同じ統合に情報品質の制御と認可の制御の両方が必要です。

## ツール統合の要素

| 要素 | 責務 | 代表的なリスク |
| --- | --- | --- |
| ツールスキーマ | 有効な入力と出力構造を定める | 曖昧なフィールドが誤った行動を生む |
| ツール結果 | 外部の観測値またはデータを供給する | 信頼できない内容を指示として扱う |
| リソース | 利用・参照するコンテキストデータを公開する | 機密データが広く発見される |
| クライアントとサーバー | アプリケーションを能力へ接続する | 信頼できないサーバーに認証情報やコンテキストを渡す |
| 認可コンテキスト | 要求をスコープと ID に結び付ける | 委任の混同や過剰な権限 |
| 監査記録 | 要求と実行内容を説明する | 証跡がなくレビューや復旧ができない |

スキーマは統合を信頼できるものにしますが、形式が正しい要求でも、認可されていない、または安全でない場合があります。アプリケーションは、要求された操作をポリシー、利用者の意図、タスクスコープ、リソースの機密性に照らして評価する必要があります。

## MCPの位置付け

MCP は、複数の AI クライアントや統合にわたり、ツール、リソース、プロンプトを一貫して公開したい場合に有用です。個別コネクターの作業を減らし、能力の説明を発見しやすくできます。ただし、API ゲートウェイ、ID システム、ガバナンスモデルの代替ではなく、相互運用性の層として理解すべきです。

MCP サーバーは有用なコンテキストを提供できますが、その内容と振る舞いには信頼性の評価が必要です。クライアントは承認済みのサーバーだけを利用し、必要最小限の能力を要求し、認証情報と機密コンテキストをタスクに限定します。

## 制御と認可の境界

ツール呼び出しでは、実行する ID、必要に応じた委任元の利用者または業務主体、承認されたタスクスコープ、意図する操作を保持します。読み取り、書き込み、承認の能力を分離します。影響の大きい操作には、生成テキストだけに依存せず、明示的な確認またはワークフロー制御を設けます。

ツール結果には外部データであることを示すラベルを付けます。これにより、検索結果、文書、リモートサーバーが返したテキストを、アプリケーションの指示を上書きする命令として解釈する可能性を減らせます。検証、レート制限、再試行、安全な失敗時の振る舞いも境界の一部です。

## 隣接するトピックとの関係

ツールと MCP は、ツール結果とリソースが実行時の振る舞いに影響するため、コンテキストエンジニアリングの一部です。[RAG](../rag/) は根拠の取得に特化し、ツールインターフェースは検索を含む幅広い能力を公開できます。AI エージェントでは計画と複数段階の実行が加わるため、認可と監査可能性がさらに重要になります。[AI エンジニアリング](../../ai-engineering/) は、これらの統合を囲むより広いアプリケーション規律を扱います。

## まとめ

ツールは、AI システムに情報とアクションへの統制されたアクセスを与えます。MCP は統合モデルの一つを標準化しますが、信頼できる利用には明示的な契約、スコープを持つ ID、検証済みの結果、観測可能な制御境界が依然として必要です。
