`AGENTS.md` は、コーディングエージェントが効果的に作業するために必要な、リポジトリ固有のコンテキストと指示を渡す Markdown ファイルです。セットアップコマンド、検証手順、コード規約、アーキテクチャ上の境界、セキュリティ上の注意、コントリビューションの流れなどを記述できます。`README.md` に似た役割を持ちますが、主な読み手は人間のコントリビューターではなく AI コーディングエージェントです。

この形式は意図的に単純です。アプリケーションレベルの制御や利用者の依頼を置き換えるものではありません。タスクごとに繰り返す必要のある、持続的なプロジェクトコンテキストを提供します。形式の概要、例、FAQ は [AGENTS.md 公式サイト](https://agents.md/)を参照してください。

## AGENTS.md とは何か

`AGENTS.md` は標準 Markdown に基づく、エージェント向けのオープンな規約です。必須フィールドや固定された見出しはありません。チームは、実際にエージェントが必要とする情報に合わせて構成できます。

よく含まれる項目は次のとおりです。

- プロジェクト概要とリポジトリ構造
- 依存関係のインストール方法と開発コマンド
- フォーマット、Lint、テスト、ビルドのコマンド
- コードスタイルとアーキテクチャ規約
- セキュリティ、データ処理、デプロイに関する注意
- コミットとプルリクエストに関する期待事項

このファイルは人間向けの文書を補完します。`README.md` はプロジェクトの目的とコントリビューターの導入に集中させ、`AGENTS.md` にコーディングエージェント向けの正確な運用情報を記載できます。

## スコープと階層

一つのリポジトリに複数の `AGENTS.md` を配置できます。ルートファイルでプロジェクト全体のルールを定め、入れ子のファイルでパッケージ、サービス、ドキュメント領域ごとの指示を追加できます。公式規約では、入れ子の指示が競合する場合、作業対象に最も近いファイルが優先します。

この階層はモノレポで有用です。ルートファイルで共通のセキュリティレビューを要求し、`packages/web/AGENTS.md` でフロントエンドのテストを、`services/api/AGENTS.md` でデータベース移行の確認を指定できます。ローカルな指示は、ルートファイル全体を複製するのではなく、広いルールを具体化するものにします。

ファイルの探索、入れ子の指示の統合、競合の報告方法はエージェントによって異なります。すべての実装が同じ方法でコンテキストを読み込むと仮定せず、利用するツールの挙動を確認する必要があります。

## 効果的な指示の書き方

効果的な指示は、具体的で、実行可能で、スコープが明確です。広い希望よりも、コマンドと観測可能な結果を記述します。「高品質にする」よりも「完了前に `pnpm lint` と `pnpm build` を実行する」の方が有用です。一般的でない制約には理由を短く添え、リポジトリが変化してもエージェントが正しく適用できるようにします。

指示は、それが適用されるコードの近くに置きます。すでに信頼できる情報源がある変化しやすい事実は複製しません。コマンドは現在のリポジトリのツールと一致させます。安全性に関わる操作では、単に注意を促すのではなく、境界と承認要件を明示します。

`AGENTS.md` を完全なアーキテクチャマニュアルにすることも避けます。詳しい背景が必要なら持続的なプロジェクト文書へリンクし、エージェントの計画、編集、検証、引き継ぎに影響する指示に集中させます。

## 限界とセキュリティ境界

`AGENTS.md` はエージェントの振る舞いを導きますが、認可の仕組みやセキュリティ境界ではありません。ファイルシステム、認証情報、ネットワーク、承認、その他の能力は、アプリケーション側で制御する必要があります。権限が過剰な状態を、文章による指示だけで安全に補うことはできません。

リポジトリの内容が信頼できない可能性もあるため、エージェントとプラットフォームは指示とデータを区別する必要があります。第三者のリポジトリ、生成されたアーカイブ、プルリクエストをレビューするとき、悪意のある、または競合する指示ファイルに触れる可能性があります。機密性の高いワークフローでは、信頼する指示の情報源を定め、重大な操作を技術的な制御の背後に置きます。

## 補足：システムプロンプトとユーザープロンプト

`AGENTS.md` の役割を理解したうえで、エージェントが受け取る可能性のある、ほかの二つの指示源との違いを整理します。

**システムプロンプト**は、エージェントを統治する振る舞いと動作境界を定めます。安全上のルール、利用できる能力、指示の優先順位、環境とのやり取りの方法などが含まれます。通常のユーザータスクの一部として書くのではなく、アプリケーションやプラットフォームから供給されます。

**ユーザープロンプト**は、「不具合を修正する」「モジュールを説明する」「ドキュメントページを追加する」といった、利用者の現在の目的を示します。タスク固有の指示であり、対象範囲や出力形式などの制約を追加することもあります。

これに対して `AGENTS.md` は、利用するパッケージマネージャーや実行すべきテストなど、リポジトリやディレクトリに紐づく持続的な指示を記録します。三つの情報源は次のように整理できます。

| 指示の情報源       | 主な目的                                             | 代表的な有効期間                   | 例                                 |
| ------------------ | ---------------------------------------------------- | ---------------------------------- | ---------------------------------- |
| システムプロンプト | 統治する振る舞いとプラットフォーム境界を定める       | アプリケーションまたはセッション   | 安全と権限に関するルールを守る     |
| ユーザープロンプト | 現在のタスクと期待する結果を定める                   | タスク                             | `AGENTS.md` の概要ページを追加する |
| `AGENTS.md`        | リポジトリまたはディレクトリ固有の作業指示を提供する | プロジェクトとともにバージョン管理 | 完了前に `pnpm lint` を実行する    |

これらは相互に置き換えられるものではありません。リポジトリ内のファイルでシステムレベルの制御を上書きしようとすべきではありません。AGENTS.md の規約では、明示的なユーザー指示が `AGENTS.md` より優先すると説明されています。それ以外の読み込み方法や優先順位の詳細は、エージェントの実装によって異なる場合があります。

## コンテキストエンジニアリングとの関係

`AGENTS.md` は、コンテキストエンジニアリングの実践的な仕組みです。タスクが実行される環境について、安定したバージョン管理可能な情報をエージェントに提供します。ユーザープロンプトが直近の意図を伝え、`AGENTS.md` がローカルな作業知識を伝え、エージェントの実行環境が統治ルールの下でそれらを選択・統合します。

この分離によって、同じプロンプトの繰り返しを減らし、リポジトリの期待事項をコードとともにレビューできます。検証コマンドや規約が変わったときには、指示をバージョン管理上で更新し、将来のタスクへ反映できるため、追跡可能性も高まります。

## まとめ

`AGENTS.md` は、コーディングエージェントに持続的なリポジトリ固有の指針を渡すための、単純でオープンな形式です。システムプロンプトが統治境界を、ユーザープロンプトが現在のタスクを、`AGENTS.md` が正確なローカルコンテキストを担うときに最も効果を発揮します。スコープを明確にし、実行可能で最新の状態に保ち、実際の権限制御と検証で支えてください。
