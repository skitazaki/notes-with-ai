データソースとは、観測、記録、測定、主張を取得する起点です。ソースは、接続に使うコネクターではなく、情報との関係によって定義されます。同じ API やファイルでも、正規の業務記録、遅延した複製、提供事業者が整備したデータセット、来歴の不明な派生データを公開できます。それぞれの意味と制約は異なります。

## 主なソース区分

- **運用・トランザクションシステム** は、注文、支払い、在庫移動、問い合わせなどの業務事象と現在の運用状態を記録します。
- **業務アプリケーション** は、ワークフロー、顧客、人事、財務、協働に関するデータを保持し、外部事業者が運用している場合もあります。
- **人が入力するソース** には、フォーム、インタビュー、注釈、調査、手作業で管理する記録があります。
- **アプリケーションや機械が生成するソース** には、アプリケーションイベント、ログ、トレース、モデル出力、機器テレメトリがあります。
- **センサーとデバイス** は、配置、較正、分解能、接続性による制約のもとで、物理条件や行動を測定します。
- **パートナーと供給者** は、別組織のプロセスと統制環境で作られたデータを提供します。
- **商用・ライセンスデータセット** は、利用、結合、保持、再配布を制限する条件のもとで取得されます。
- **公共・オープンデータ** は、明示されたライセンス、方針、公的使命に基づいて広く公開されます。
- **ウェブ由来データ** は、可用性、意味、利用条件、構造が予告なく変わり得るウェブ資源から観測されます。

これらの区分は重なることがあります。パートナーフィードが運用システムに由来し、公開データセットがセンサー観測を集約している場合もあります。区分は、所有者、正規性、制約を明らかにするときに意味を持ちます。

## 正規性と所有者

**System of Record** は、定義された事実やプロセスについて正規と認められたシステムです。ただし、保持するすべての項目について正規とは限りません。顧客対応システムは問い合わせ状態の正規ソースであっても、顧客住所は別システムから複製している場合があります。

**二次ソース** は、別の情報源を複製、変換、集約、再公開します。アクセスしやすく安全な場合もありますが、遅延、フィルタリング、定義変更、訂正方法の不明確さが生じます。可能であれば、直接参照したソースと元の正規ソースの両方を記録します。

ソース所有者は、データを説明し、アクセスを承認し、誤りを訂正し、変更を通知し、収集による負荷を受け入れる責任者を明らかにします。技術的な保管責任だけでは正規性を確立できません。外部データでは、元の組織、公開者、再販者、社内の契約責任者に責任が分かれる場合があります。

## ソースの評価

一律の信頼スコアではなく、利用目的に照らして候補を評価します。

| 観点       | 確認する問い                                               |
| ---------- | ---------------------------------------------------------- |
| 正規性     | 誰がその事実を作り、この用途の正規ソースと認められているか |
| 来歴       | 起源、収集方法、版まで追跡できるか                         |
| 信頼性     | 欠落、訂正、遅延、停止が可視化されているか                 |
| 変動性     | 値、定義、インターフェース、可用性がどの程度変化するか     |
| アクセス性 | 技術的に取得でき、組織として許可されているか               |
| 網羅範囲   | どの母集団、事象、地域、期間が含まれ、何が欠けるか         |
| 制約       | 運用、法務、契約、倫理、コスト、レートの制限は何か         |

信頼性は用途に依存します。更新の速い二次フィードは状況把握に適しても、財務照合には不適切な場合があります。System of Record であっても、測定誤差があったり、業務フロー外の活動を含まなかったりします。

## 一次データと派生データ

**一次データ** は、現在の目的のために直接収集するか、観測対象のソースから直接取得します。**派生データ** は、変換、推論、集約、結合、再公開によって作られます。この区別は、値の解釈や訂正可能性に影響しますが、一次データが常に正確で、派生データが常に劣るわけではありません。

観測と推論を区別し、ソース、所有者、収集方法、観測時刻、処理履歴、制限を特定できる [メタデータ](/ja/docs/data/metadata/) を保持します。 [データアーキテクチャ](/ja/docs/data/architecture/) は、ソースをシステム全体の構成へ位置づけます。ソースと収集範囲が確定した後の確実な転送は、 [データ取り込み](/ja/docs/data/engineering/ingestion/) が扱います。

## まとめ

ソース選定は、データセットが引き継ぐ正規性、網羅範囲、継続性、制約を決めます。ソースを単なるレコード取得先ではなく、来歴と限界が明らかな、責任を持つ情報の起点として扱います。
