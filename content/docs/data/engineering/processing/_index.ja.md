データ処理（Data Processing）は、ソースデータや中間データを、アプリケーション、分析、AI システムが利用できるデータセットへ変換します。フィルタリング、結合、集計、参照データによる付加、スキーマ変換、前提条件の検証などを行います。

```mermaid

  Ingestion["取り込み"] --> Processing["処理"] --> Delivery["配信"]
```

## 変換操作

- **フィルタリング** — 対象範囲外のレコードを除外する
- **射影と再整形** — フィールドの選択、名前変更、入れ子化、正規化を行う
- **結合** — 共通キーや時間関係でレコードを組み合わせる
- **集計** — 定めた粒度で指標を計算する
- **付加** — 分類、参照値、派生属性を追加する
- **検証** — 構造やドメイン上の期待を公開前に確認する

各操作では入力の前提と出力粒度を明示します。技術的に成功した結合でも、キーが一意でなかったり有効期間を無視したりすれば、誤解を招く結果になります。

## ETL と ELT

**ETL（Extract, Transform, Load）** は、対象の提供システムへデータを格納する前に主要な変換を行います。**ELT（Extract, Load, Transform）** は、ソースデータを先に永続化し、対象プラットフォーム上で変換します。

これは変換場所の違いであり、設計品質の優劣ではありません。軽い検証や保護を格納前に行い、再実行可能な入力を保存してから豊かな変換を行うなど、両者を組み合わせることも一般的です。

## バッチ処理

バッチ処理は、ファイル、テーブルスナップショット、時間区間など境界のある入力を扱います。定期レポート、大規模再計算、照合、バックフィルに適しています。

- 完全で再現可能な入力境界を定義する
- 独立単位へ分割して並列実行する
- 出力の置換やマージを冪等にする
- バックフィルを現行処理から分離する
- 大規模再計算の資源とコストを制御する

## ストリーム処理

ストリーム処理は継続的なイベントを扱い、イベントごと、またはイベント時刻のウィンドウ単位で結果を更新します。

- **イベント時刻と処理時刻** — 異なる時間上の問いを区別する
- **ウィンドウ** — 無限のストリーム上で集計範囲を定める
- **状態** — 集計、結合、重複排除の情報を保持する
- **チェックポイント** — 障害後に状態を復元可能にする
- **遅延イベント** — 既出結果を訂正する方針を定める
- **リプレイ** — 保持イベントから状態や結果を再構築する

## 分散処理の基礎

**パーティショニング** はレコードを並列作業単位へ割り当てます。偏りがあると一部のワーカーだけが過負荷になります。**並列性** は処理能力を高めますが、入力配置、共有サービス、調整コスト、資源に制約されます。

**シャッフル** は結合やグループ化のためにワーカー間でレコードを再配布し、ネットワーク、ディスク、直列化、同期のコストを伴います。**状態** は分割・永続化・一貫した復旧が必要です。**耐障害性** はタスク、ワーカー、依存先が失敗したときの動作を定めます。

Spark、Flink、SQL エンジン、dbt などは異なる処理環境の例です。製品を処理の定義にせず、ワークロードのセマンティクスと運用制約から選択します。

## 処理セマンティクスとアーキテクチャ

処理セマンティクスは、入力の有界性、順序、状態、レイテンシ、訂正、一貫性、リプレイといった必要な挙動を表します。アーキテクチャは、それをどこでどのように実装するかを決めます。データエンジニアリングは、選ばれた構造の中で挙動を信頼できるものにします。

例えば、イベント時刻に基づく移動集計には、マネージドサービスかオープンソースエンジンかにかかわらず、キー単位の状態と遅延イベントの方針が必要です。日次再計算には、ストレージがウェアハウスかレイクハウスかにかかわらず、安定した入力境界と冪等な公開が必要です。

アーキテクチャはシステム構造と主要な設計判断を表し、エンジニアリングはその構造の中で処理動作を信頼できるものにします。

## 信頼できる出力の生成

処理内の検証は定義済み期待を実装しますが、用途に対する適合性を単独で定義するものではありません。より広い品質領域は [データマネジメント](/ja/docs/data/management/) と [データ品質の次元](/ja/docs/data/management/data-quality-dimensions/) を参照してください。スキーマ、リネージ、所有、影響分析には [メタデータ](/ja/docs/data/metadata/) が必要です。

[データオーケストレーション](../orchestration/) は処理の実行時期、依存関係、障害時の対応を調整し、 [データ可観測性](../observability/) は本番環境における処理の挙動を明らかにします。
