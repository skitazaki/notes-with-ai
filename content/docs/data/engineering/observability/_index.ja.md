データ可観測性（Data Observability）は、データパイプラインとデータフローの運用状態を理解するためのシグナルと文脈を提供します。**データシステムで何が起きており、なぜ起きているか**という問いに答えます。

監視は既知の状態を確認します。可観測性は複数のシグナルと依存関係を組み合わせ、事前に予測していなかった状態の調査を可能にします。

```text
パイプライン
├── 実行
│   ├── 状態
│   ├── 所要時間
│   └── 障害
│
├── データフロー
│   ├── 鮮度
│   ├── 量
│   └── スキーマ
│
└── 依存関係
    ├── 上流
    └── 下流
```

## 運用シグナル

### パイプラインの健全性と実行

実行状態、タスク所要時間、再試行回数、待機時間、資源利用、障害分類は、処理が開始、進行、完了、停止したかを示します。ログとトレースは診断詳細を、デプロイと設定履歴は障害前の変更を示します。成功したタスクでも、入力がゼロ、出力が異常に少ない、利用者の期限より遅い可能性があります。

### 鮮度とレイテンシ

**鮮度** は、利用可能なデータセットがソースまたは期待更新時点に対してどれだけ新しいかを示します。**レイテンシ** はフローの一部または全体に要した時間です。ソース公開、取り込み遅延、待機、処理、提供を含めて評価します。

### スループットと量

レコード数、バイト量、パーティション、イベント流量の変化は、入力の欠落、重複、遅延、急増を示すことがあります。障害だけでなく、正当な業務イベントや上流の挙動変更もあり得ます。可観測性は変化と文脈を示しますが、ドメイン上の期待なしに用途適合性を判断するものではありません。

### スキーマ変更

フィールドの追加、削除、型変更、互換性違反は、フローを壊したり意味をサイレントに変えたりします。スキーマ版を取得し、生産者、パイプライン、利用者の間で比較します。

### 依存関係とリネージ

障害の重要度は依存関係で変わります。上流依存は原因特定を、下流リネージは影響を受けるデータセット、ダッシュボード、アプリケーション、AI ワークフローの特定を支えます。詳細は [メタデータ](/ja/docs/data/metadata/) を参照してください。

## アラート

アラートは、すべての異常値ではなく、対応可能な状態を表すべきです。対象資産、観測値と期待値、重大度、時間範囲、直近変更、依存関係、所有者、調査開始点を含めます。

明確な上限には固定しきい値が使えます。変化率や異常検知は予測しにくい挙動を捉えますが、季節性や通常変動への対応が必要です。ルーティング、グループ化、抑制、エスカレーションによりノイズを減らします。

アラートは対応の開始点であり、可観測性の最終成果ではありません。状況把握のダッシュボード、調査に利用できる証拠の保持、継続改善のためのサービスレベル報告も必要です。

## インシデント調査

1. 影響を受けるデータ資産と利用者を特定する
2. 発生時刻と違反したサービス期待を確認する
3. コード、設定、スキーマ、ソース、インフラの直近変更を調べる
4. リネージと依存関係を上流へたどり、最初の異常シグナルを特定する
5. 再試行、リプレイ、ロールバック、バックフィル、隔離の安全性を判断する
6. 復旧結果を検証し、残る不確実性を下流へ伝える

相関 ID、実行 ID、データセット版、イベント位置、デプロイ記録が、この調査を再現可能にします。

## 可観測性とデータ品質

**可観測性が答える問い：** データシステムで何が起きており、なぜ起きているか。

**データ品質が答える問い：** データは、意図した用途に必要な期待を満たしているか。

鮮度、予期しない量、スキーマドリフト、分布変化は、運用と品質の両方のシグナルになり得ます。違いは目的です。可観測性は運用と診断のためにシステムとデータの挙動を明らかにし、データ品質管理は用途適合性に関する期待を定義、測定、統制します。

パイプラインのチェックは品質ルールを実装でき、可観測性は結果を報告できますが、どちらも業務上の許容性を暗黙に定義すべきではありません。 [データマネジメント](/ja/docs/data/management/) と [データ品質の次元](/ja/docs/data/management/data-quality-dimensions/) を参照してください。

## 診断可能性を設計する

可観測性は完成後に全面的に追加できるものではありません。 [データ取り込み](../ingestion/) はイベント時刻、取り込み時刻、ソース位置、リプレイ情報を保持し、 [データ処理](../processing/) は入出力版、パーティション境界、変換 ID を記録し、 [データオーケストレーション](../orchestration/) は状態、パラメータ、試行、依存関係を公開します。

これらのシグナルにより、何が実行され、どのデータを扱い、どの出力を作り、誰が依存し、再試行やバックフィルが重複・不整合を生まないかを判断できます。
