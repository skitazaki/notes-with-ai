オープンデータとは、来歴とオープン性を保つための条件を除き、誰もが自由にアクセス、利用、変更、共有できるデータです。広い [データ共有](/ja/docs/data/sharing/) の中に位置する公開・再利用モデルです。

無料で閲覧できるだけでは十分ではありません。持続可能なオープン性には、法的許諾、実用的なアクセス、機械可読形式、十分な説明、権利と正当な制約を守るガバナンスが必要です。

## データをオープンにする条件

[Open Definition 2.1](https://opendefinition.org/od/2.1/en/) は、誰もがアクセス、利用、変更、共有できるものとしてオープンな知識を説明しています。公開 URL があるだけでは満たせません。

| 観点       | 要件                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 法的       | オープンライセンスまたはパブリックドメインにより再利用と再配布を許可     |
| 技術的     | 機械可読かつ非差別的な形式で提供                                         |
| アクセス   | 不要な登録や交渉なしに取得可能                                           |
| メタデータ | 範囲、来歴、単位、スキーマ、品質、更新方法を理解可能                     |
| 運用       | 安定して公開され、版管理され、長期的に保守                               |
| 権利と安全 | 公開前にプライバシー、機密性、セキュリティ、知的財産、共同体への害を検討 |

「公開アクセス可能」と「オープンライセンス」は同義ではありません。ダッシュボードは公開されていても抽出・再利用を禁じている場合があり、ライセンスのないファイルでは合法的な用途を判断できません。

## 目的を伴うオープン・バイ・デフォルト

[Open Data Charter](https://opendatacharter.org/principles/) は、原則公開、適時かつ包括的、アクセス・利用可能、比較・相互運用可能、統治と市民参加への活用、包摂的な発展とイノベーションへの活用という六原則を示します。

オープン・バイ・デフォルトは政策上の推定であり、すべてを公開する指示ではありません。個人のプライバシー、機密性、安全保障、保護される文化・共同体の知識、契約上の義務、知的財産、他データとの結合リスクは正当な制限理由です。

公開には目的も必要です。期待する公共的成果、想定利用者、影響を受ける共同体、正確で利用可能な状態を保つための資源を検討します。

## オープンデータのアーキテクチャ

- 分類と開示審査を含む公開ワークフロー
- 安定したデータセット識別子と版情報
- データセットと配布物に付随するオープンライセンス
- 検索可能なメタデータを持つカタログ
- オープンで説明された形式による一括ダウンロード
- 利用者を差別せず有用性を高める API
- 来歴、品質、時間・地理範囲、更新予定
- 変更通知、アーカイブ、訂正、廃止手順
- 全利用者の追跡を必要としないフィードバックと効果測定

[DCAT 3](https://www.w3.org/TR/vocab-dcat-3/) は概念上のデータセットと、その配布物やデータサービスを区別します。一つのデータセットを CSV、JSON、API などで提供しながら、共通の識別子とメタデータを保てます。

## ライセンスと帰属表示

オープンライセンスはアクセス、利用、変更、再配布を明確に許可すべきです。帰属表示や派生物のオープン性を求めるものもあります。利用者、活動分野、商用目的による差別的な制約は、一般に Open Definition の要件と両立しません。

データ結合時にはライセンス互換性が重要です。帰属要件は大規模利用でも実行可能にし、公開者がライセンスを付与する権限を持つことを確認します。

## プライバシーと責任ある公開

オープンな公開は取り消しが困難です。一度コピー・再配布されると、アクセス制御や失効では回収できません。そのため開示審査は公開前に行います。

氏名の削除だけでは不十分な場合があります。希少属性、位置、時刻、他の公開データとの結合から個人や機密集団を再識別できます。 [データプライバシー](/ja/docs/data/privacy/) の目的制限、最小化、透明性、保持などを適用し、集約、一般化、合成データ、遅延公開、制御アクセスも検討します。

個人データでなくても、安全保障、環境上の機密性、先住民データガバナンス、差別、データ活用能力の非対称性によって共同体へ影響し得ます。

## 品質、利用可能性、保守

定義、単位、コード、識別子、収集方法、制約、既知の欠損、更新頻度、問い合わせ経路を提供します。安定した識別子と版履歴は引用と再現を支え、機械可読スキーマと標準語彙は比較を容易にします。

一括ダウンロードは API 依存を避け、API は選択的で最新の利用を支えます。どちらも、意味が不明確または保守されていないデータを補うことはできません。

## 価値と測定

オープンデータは透明性、説明責任、研究、公共サービス、市民参加、教育、商業イノベーションを支えます。鮮度、可用性、説明の完全性、研究やサービスでの再利用、問題解決、利用者の多様性、公共的成果を測ります。ダウンロード数だけでは、理解、有用性、公平なアクセスは分かりません。

## よくある失敗

- 明示的なオープンライセンスなしに公開する
- 人間向けダッシュボードや独自形式だけを提供する
- 直接識別子の削除を匿名化とみなす
- 需要の高いデータより低価値な掲載数を優先する
- 定義、来歴、制約、更新責任を示さない
- 版管理と通知なしに URL やスキーマを変更する
- 在庫数とダウンロード数だけで成功を測る
- 制御された共有より常に安全で価値があると考える

## まとめ

オープンデータは、広く非差別的な再利用のための統制された共有です。最大限の公開ではなく、公開後に回復できない人々、共同体、安全、権利を守りながら、適切なデータを真に再利用可能にすることが目標です。
