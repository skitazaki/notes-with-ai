データクリーンルームは、参加者全員に基礎レコードへの無制限なアクセスを与えず、機密データから許可された洞察を導くための統制されたアーキテクチャおよびガバナンスパターンです。

特定製品や単一のプライバシー強化技術を指す言葉ではありません。参加者、目的、脅威モデル、許可する処理、出力制御、証跡、責任境界を明示して初めて信頼できる仕組みになります。

## クリーンルームが必要な理由

オーディエンス重複、広告効果測定、不正分析、医療研究、サプライチェーン連携、モデル評価などでは、生データを通常の方法で集約できない場合があります。

クリーンルームは共有の接点を変えます。参加者がデータを持ち込むか遠隔利用可能にし、制約された環境で承認済みの処理を行い、許可された結果だけを外部へ出します。

## 中核となる制御レイヤー

| レイヤー       | 責任                                                   |
| -------------- | ------------------------------------------------------ |
| 参加           | 組織、利用者、ワークロード、承認目的を識別             |
| 入力           | データセット、項目、版、持ち込み条件を限定             |
| 計算           | 承認済みクエリ、関数、結合、モデル、テンプレートを許可 |
| プライバシー   | 最小化、閾値、抑制、ノイズ、暗号保護を適用             |
| 出力           | 結果を審査、フィルター、集約、遅延、制限               |
| 証跡           | リネージ、クエリ、判断、版、公開結果を記録             |
| ライフサイクル | 保持、失効、事故対応、終了を定義                       |

制御は組み合わせて機能させます。テーブルへの直接アクセスを禁じても、反復クエリで個人レコードを再構成できれば不十分です。

## アイデンティティ照合と結合リスク

多くの用途では、同じ人物、世帯、端末、企業、イベントを示すレコードを照合します。ハッシュ化識別子、トークン、信頼できるアイデンティティサービス、プライベート集合積などを利用できます。

入力を推測・照合できるなら、識別子のハッシュ化は匿名化ではありません。照合によってデータセット間に新たな関係が生まれ、識別可能性が高まることもあります。識別子を最小化し、照合品質と偏りを記録し、許可する結合を制限する必要があります。

## プライバシー強化技術

- **差分プライバシー**：明示したモデルと予算の下で、個人の参加が結果へ与える影響を限定する
- **秘密計算**：各当事者の入力を互いに開示せず共同計算する
- **プライベート集合積**：一致しない要素の開示を抑えながら共通要素を特定する
- **準同型暗号**：暗号化した値に対して限定された計算を行う
- **コンフィデンシャルコンピューティング**：構成証明可能なハードウェア実行環境で使用中データを保護する

[NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final) は差分プライバシー保証の評価指針を、 [NIST Privacy-Enhancing Cryptography](https://csrc.nist.gov/Projects/pec) は暗号メカニズムを説明しています。 [Confidential Computing Consortium](https://confidentialcomputing.io/about/) はコンフィデンシャルコンピューティングを、ハードウェアベースで構成証明可能な信頼実行環境を中心に定義しています。

これらはメカニズムであり、利用の適切性を判断するガバナンスそのものではありません。

## 脅威モデル

正直だが好奇心を持つ参加者、過失、侵害、悪意ある行動を区別します。他者の生レコード推測、特権管理者によるアクセス、小集団を分離する反復クエリ、共謀、悪意ある分析コード、外部データとの結合、古い権限や資格情報を考慮します。

## 出力ガバナンス

出力制御は最も重要な境界になり得ます。最小集約数、希少値の抑制、次元の制限、ノイズ付加、頻度制限、モデル成果物の審査、例外的な持ち出しへの人的承認などを適用します。

出力には、入力版、承認目的、実行コードやクエリ、プライバシーパラメーター、ポリシー判断、受領者を追跡できる来歴が必要です。

## 運用モデル

データ準備、ポリシー定義、基盤運用、クエリ承認、プライバシー審査、事故対応、監査の役割を合意します。参加と離脱の手続きでは、データ検証、目的変更、資格情報の更新、保持された出力、協業終了を扱います。

## よくある失敗

- 「クリーンルーム」という名称自体をプライバシー保証と考える
- 再構成や合成リスクを分析せず任意クエリを許可する
- ハッシュ化識別子を匿名とみなす
- 入力のみを保護し、出力を統制しない
- 構成証明、コード、鍵解放ポリシーを検証せず TEE を使う
- 失効時にモデル成果物や派生データを無視する
- 機密性を統制せず詳細ログを収集する

## まとめ

データクリーンルームは、共有関係を承認済み処理と統制された出力に限定します。許可する結果と脅威モデルから設計を始め、その結果に必要な最小限のデータと、釣り合いの取れた強い制御を選びます。
