データ分類は、機密性と事業上の重要度を、保護、アクセス、共有、監視、保持、廃棄で利用できる取り扱い要件へ変換します。システム動作や運用判断を変えないラベルは保護に寄与しません。

## 分類の軸

- **機密性**: 不正開示の影響。公開、社内限定、機密、厳秘などで表します。
- **事業上の重要度**: 改ざん、利用不能、破壊の影響。機密でなくても重要なデータはあります。
- **規制・契約上の機微性**: 特別な取り扱い義務。個人情報の適切な利用は [データプライバシー](/ja/docs/data/privacy/) で判断します。
- **完全性と真正性**: 不正変更や不明確な来歴が重大な害を生むかを示します。
- **ライフサイクル状態**: 有効、共有中、アーカイブ済み、期限切れ、削除待ちを区別します。

一貫して適用できる少数の段階に絞り、定義、例、所有者、標準の取り扱いプロファイルを定めます。

## ラベルから統制へ

| 領域     | 判断の例                                                  |
| -------- | --------------------------------------------------------- |
| 保存     | 許可された場所、暗号化、環境分離                          |
| アクセス | 対象ロール、承認、特権制限                                |
| 処理     | ノートブック、ログ、テスト、AI プロンプトで生値を使えるか |
| 共有     | 受領者、インターフェース、変換、境界                      |
| 移動     | 転送時保護、許可地域・ネットワーク                        |
| 監視     | 監査粒度、アラート閾値、レビュー                          |
| 廃棄     | 削除方法、レプリカとバックアップの扱い                    |

ID と認可ポリシーは [アクセス制御](/ja/docs/acc/) で扱い、分類は判断に必要な属性と文脈を提供します。

[メタデータ](/ja/docs/data/metadata/) には分類値、範囲、生成元、確信度、確認者、時刻、取り扱いプロファイルを記録します。自動検出は候補を提示できますが、曖昧な意味や重大な判断には人の確認が必要です。派生データでは、集約で露出が下がる場合や結合で上がる場合があるため、単純コピーではなく変換の意味を評価します。

早期に分類し、未分類を最も緩く扱わず、検出と承認を分離し、分類へ再利用可能な統制を結び付け、変更後に再評価し、実際の適用をテストします。

## まとめ

分類はデータに関する知識を適用可能な動作へ接続します。理解できるラベルをメタデータとして記録し、文脈を保って伝播させ、具体的な統制へ対応付けます。
