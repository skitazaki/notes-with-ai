データ保護技術は、値の表現や利用者へ示す詳細度を変えて露出を抑えます。マスキング、トークン化、墨消し、ハッシュ化、仮名化、集約は異なる問題を解決し、相互に交換できません。

| 技術       | 可逆性                     | 参照整合性               | 用途                                   |
| ---------- | -------------------------- | ------------------------ | -------------------------------------- |
| マスキング | 方法による                 | 任意                     | 非本番、サポート、分析ビューで値を隠す |
| トークン化 | 保護された対応表で可逆     | 多くの場合必要           | 安定 ID を置換し結合を維持する         |
| 墨消し     | 公開出力では不可逆         | 通常不要                 | 文書、ログ、応答から内容を除去する     |
| ハッシュ化 | 一方向                     | 決定論的なら一致判定可能 | 完全性確認、認証情報検証、限定照合     |
| 仮名化     | 追加情報で多くは再対応可能 | 多くの場合必要           | 直接識別子を作業データから分離する     |
| 集約       | 直接は不可逆だが推測可能   | グループ単位             | 行単位ではなく統計を公開する           |

マスキングは値を置換、攪乱、一般化、部分非表示にします。墨消しは公開物から内容を除去し、見た目だけを覆って元文字列を残してはいけません。トークン化は代替値と保護された対応サービスを使い、安定した結合を可能にする一方、対応サービス自体を高価値資産にします。

仮名化後も外部情報や希少属性から再対応できる可能性があります。適切な利用は [データプライバシー](/ja/docs/data/privacy/) で判断します。ハッシュ化は低エントロピーの識別子を安全に秘匿できず、集約も小集団や反復クエリから構成員を推測される場合があります。

元の値の復元、安定した結合、攻撃者が得られる補助情報、希少値や関係、元データ・対応表・鍵の保管、出力の再結合可能性を確認して選択します。
